2. 盤點分支/PR/Issue、上次 commit 與未決問題，避免重複開工。
3. 不重開已完成的 52 題訪談；如需變更，寫清原決策、修訂、理由、影響、核准者。
4. 優先研究成熟官方/商用/開源方案並內化；鎖版本、授權與來源，不能無必要重造輪子。
5. 文件、程式、測試與狀態需在 GitHub 留證據；開發前建立明確驗收標準；失敗時保留原因與可重現步驟。

7. 研究候選 ≠ 技術選型 ≠ 已實作 ≠ 已驗證。嚴格區分狀態。
8. 優先透過分支與 PR 提交重要變更，勿未經審查直接合併主分支；不得假稱已完成獨立審查。
9. 不將真實客戶個資、授權受限字型、商業 AI 設計原檔及密鑰上傳倉庫。
