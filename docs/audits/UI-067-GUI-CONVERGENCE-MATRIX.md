## 5. 後續收斂流程與驗收

1. UI-068 問題必須先顯示它與 UI-028／029、UI-014／015／057、UI-048 的不同，**只問獨立問題報告是否必要及最小檔案交接形式**。
2. 每次 Human 作答後，文件區分「決策已批准」與「具體技術方案待驗證」，更新 `CONTINUATION.md` 和此矩陣（若其分級有變），不得留下過期「下一題」作唯一來源。
3. 全部實質 GUI 缺口結案後，建立單一規格與未來驗收追蹤，將 Q 基線、UI 系列、優先級與版本差異對帳；不必問到 UI-075，亦不因達到題號就自動發出完工聲明。
4. **本輪未開始任何程式開發、實際檔案轉換、訓練、印前輸出、驗收測試或獨立審查**；矩陣是可供日後審查的準備文件。
