## 1. 當前訪談範圍與順序

現在討論資料表示、可學特徵、模型輸入／輸出、參數與依賴、可辨識性、訓練／驗證與失敗狀態。先前「合格集合／標記是否存在」尚未獲答，保留為後續資料準備問題，不代選答案。

順序為：反推模型資訊需求 → 定義觀察／欄位／群組與訓練目標 → 設計學習方法和參數 → 取得版本化訓練結果及明確驗證範圍 → 再討論輸入限制、按鈕、拖曳、預覽、確認及輸出交互。

現有互動需求用於檢查模型資訊是否足夠；目前不討論畫面／操作政策。資料資格、真實字型與來源可信度仍是必要的資料處理問題，不以延後互動為由假定已解決。

## 2. 從已知需求反推的訓練資訊

| 已知未來用途 | 模型／資料處理必須提供的資訊 |
|---|---|
| 資料移到另一候選位置 | 等效欄位群、角色與容器對應、語意／歸屬限制、尺寸／字型／文字能力及替代條件 |
| 改動相對位置 | 欄位／群組關係圖：上下左右、先後、同基線／邊界、間距、錨點、包含關係與可變範圍 |
| 依輸入容量引導限制 | 按尺寸／家族／角色組合／實際字型與固定pt條件化的欄位數、字串長度與實測占用之聯合可行域 |
| 對新組合自動排列 | optional/repeat/收合／擴展／換列文法、合法拓撲、容器能力、相容角色與適用條件 |
| 保持已學風格 | [合格訓練作品風格適合區域](2026-10-18-QUALIFIED-TRAINING-STYLE-SUITABLE-REGION.md)：對齊／字級層級／ScaleX／tracking／留白／密度的聯合條件分布與多種風格子群 |
| 判定能否相信結果 | 來源與觀察可信度、有效lineage支持、反例、不確定／未知、模型／規則／資料／政策版本與驗證範圍 |

學習結果應含結構、關係、條件及證據。只有一張最佳座標稿或一個總分不足以支持這些用途。建議在既有TrainingStore與模型／規則版本中保存上述型別紀錄，不新增平行資料庫或公開API平台。

## 3. 要區分的模型概念

- **欄位與顯示實例**：語意欄位ID／主人與幾何框／文字run分開；一筆多行或多次印出不改資料身份，空間負擔仍按實際實例計。
- **結構角色等效與條件替代**：可先以同角色／語意／政策相容群建模；跨語意的可替代關係另帶來源與可行條件。後者可能有方向、不對稱、也不具傳遞性，不能直接當數學等價類合併。是否本階段同時學跨類替代，留待下一個模型問題確認。
- **關係與絕對座標**：保留mm與正規化幾何，但以群組／角色關係、baseline、anchor與gap條件作可重用規則。角色之間的學習偏好不自行升為硬限制。
- **適合區域與容量邊界**：已確認合格TRAIN作品是風格基準；欄位數與字串長度等需聯合估計，不能把各自最大值組合成不存在的能力。只有有界搜尋／資料支持時，明示best_found／validated／UNKNOWN等狀態，不冒稱全域最大值。
- **模型與確定性規則**：語意身份、固定pt政策、來源／字型／Logo／正式Gate及版本柵欄仍由核准規則負責；學習提供有證據的風格／能力模型。既有Qt量測、圖結構、聚類／穩健統計、Kiwi與條件文法分工沿用[工程參考](../dev/AI_CROSS_WORK_ENGINEERING_REFERENCES.json)。

## 4. 參數設計需要明確的欄位

每組可學參數保存：單位／正規化方式、所屬角色與群組、條件特徵、來源可信度、獨立支持／反例、分布或區域表示、與其他參數依賴、缺失策略、訓練／驗證資料角色與版本。

由作品推估位置／間距／文字風格與容量，與訓練超參數／搜尋預算分開。超參數可用VALIDATION選型；不要求使用者猜數字，不因訓練結果增加自由度而改寫硬政策。跨作品lineage隔離、封存TEST及UNKNOWN規則維持。
