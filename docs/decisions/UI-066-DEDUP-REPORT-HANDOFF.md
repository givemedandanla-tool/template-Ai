## 二、唯一保留的待補充規格（尚未獲得具體檔案格式／交接方式選擇）

### UI-066-R1｜獨立診斷報告的格式與內容封裝（OPEN）

- 決定是否需要與 UI-028 **卡片預覽檔**相區別的獨立「問題／證據報告檔」、預設格式（例如 PDF／HTML／結構化資料的方案**僅為待比較候選，並非核准格式**）、可閱讀性／可機器讀性及內容摘要層級。
- 依既有 UI-014／015／057 **同一診斷資料與 exact 版本**輸出：當次作品／候選／物理尺寸識別、規則／模板／來源快照、實際失敗與證據不足分流、受影響欄位／合法修正入口、產製時間、是否完成全體候選搜尋、輸出時的驗證結果與未驗證事項。
- 是否附帶可辨識的**非正式**縮圖、位置標記、問題清單、版本與掃描的來源連結，須考慮尺寸與來源保護。**報告不可反向寫入正式主檔、模板、訓練資料或印前 PASS**。

### UI-066-R2｜本機保存／人工交接與個資安全（OPEN）

- 決定從哪個既有問題介面產製報告、預覽／選擇保存至何處、與 UI-029 的檔案安全命名／覆寫確認是否共用同一檔案處理機制（應優先 REUSE）。
- 決定交接方式：本機檔案、使用者自行分享的去識別版本、是否包含必要來源索引及如何重新定位到原工作。任何外部傳送都需明確授權，**不預設雲端上傳／寄送／同步**。
- 重用 UI-048 既有個資最小揭露／授權設計：分享前審查姓名、電話、Email、LINE、IG、客戶編號、來源檔路徑、附圖及中介資料是否可識別客戶；遮罩須作用到實際匯出內容、縮圖／附件／中介資料，**不是只有 GUI 畫面打馬賽克**。需考量可單獨打開的報告無法存取本機隱私原始資料。
- 報告須有「歷史快照／非正式問題紀錄／不代表當前驗證或正式印刷可用」的醒目識別；原資料更新或問題修復後，不得以舊報告宣告最新 FAIL／PASS。是否提供「重新對帳本機現行版本」屬未來待評估互動，不新增永久案件庫。
- 若格式／隱私／來源證據不足，應阻擋不安全的「對外分享用報告」，保留合法的既有畫面診斷，不為了讓報告成功而偽造資料。

**注意：R1、R2 是明確保留的未決規格，不是目前已採納 PDF、HTML、JSON、任何具體分享流程或已能產生檔案。** 未來只有確認必要性且既有 UI-028／029／048 無法完全覆蓋時，才提出**僅限此缺口**的選擇題；不可重問整體診斷功能。

## 三、跨決策測試要點（待未來開發授權後才可實際驗收）

1. 原有 UI-014／015／057 的輸入錯誤、問題位置與分類保持完全相同；不因報告形式不同產生兩套真值。
2. 已證實無解與缺少證據的區別保持，報告要標示版本、時間與未完成搜尋條件；不能把預估風險寫成已確認硬性無解。
3. 報告/非正式預覽與正式印刷輸出仍按 UI-027／028 區分，從報告返回畫布不得解除 Gate。
4. 去識別內容須完整覆蓋文案、來源圖片、路徑與附檔的敏感資訊；不得用只遮罩螢幕或刪掉電話字串就假稱已完整去識別。
5. 文件不存在、磁碟滿、權限失敗、命名衝突等按 UI-029／030 既有安全保存規則處理；不得回報已保存。
6. 不另建平行錯誤中心、永久病例／訂單資料庫、AI 診斷演算法、角色權限系統或上傳服務。
