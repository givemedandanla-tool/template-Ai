# 使用者核准：checkpoint、開發紀錄與功能證據優先

2026-10-13 使用者指令原文：

1.「之後的template Ai開發工作都需要有check point，避免任何意外導致的工作進度丟失」
2.「工作紀錄要持久化到github，讓human開發人員能閱讀，也能讓AI(也就是GPT)，可以閱讀，並知道下一步的開發計畫」
3.「製作程式要求與功能清單，並在清單上紀錄功能是否完成實作，若完成實作要附上證據，但如何附上適合AI覆核的證據，我需要你參考當前商用方案和開源專案的思路，設計出方案向我報告」
4.「開發過程中0對話、持久化是程式開發核心宗旨，於是2跟3的文件要能讓gpt主動知道要去閱讀」
5.「為了避免重複嘗試打包成exe,之後的開發要著重於達成程式要求與功能清單上的目標（有些程式完善後才要設計的需求除外），不必要求打包成exe」
6.「先完成上述五點的框架後，再繼續開發」

## 採用

根 AGENTS 與 Copilot 指令連到 STATE／交接／機器清單／Human 清單／工作紀錄。每工作包與 10 分鐘保存 checkpoint，本機 PREPARED 與 GitHub 讀回 REMOTE_VERIFIED 分開。逐項來源／環境／測試／匿名附件做證據，保留所有未完成與延後需求。使用既有授權自主推進，不做例行確認；真正缺資訊記 BLOCKED，不猜未決產品方案。

EXE 不作本期目標，停用 push／PR 的打包觸發，只保留未來人工 dispatch；不重試舊打包。新的功能／治理 CI 與本地測試可執行，但不等待 EXE 才宣稱具名子範圍完成。框架證據與 READY checkpoint 完成後，下一包為 CORE-023 来源快取完整性。

方案、成熟來源及限制見 `docs/dev/EVIDENCE_DESIGN.md`；不是 UI-066 產品診斷報告的新增格式決策，不要求額外訪談。較新規範取代歷史文件中「先解 EXE」的開發優先順序。
