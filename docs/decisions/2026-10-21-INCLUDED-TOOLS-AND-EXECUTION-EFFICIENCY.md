# 既有方案正常使用與執行效率

日期：2026-10-21。使用者確認GitHub未設定付款方式、目前未持有API key，並要求修正過度保守的費用規定，不自我設限，保持執行效率。這是對先前「單一Codex」「無帳務證據就不推送／不使用代理」規定的後續修正；舊任務與驗證紀錄保留為歷史。

## 現行規則

1. **既有能力預設可用。** 本次環境已提供的ChatGPT Pro／Codex能力與合理使用額度、免費本機工具、正常GitHub讀寫與既有標準CI，依任務範圍直接使用。不要求使用者另交帳單、方案截圖、API key或逐項費用證明；不因帳務API不可讀而停止普通開發與保存。
2. **移除單一Codex的費用禁令。** 不再以未知的額外代理費用限制既有內建能力。是否啟用子代理仍依任務授權與平台／較高優先指令；允許時按獨立子任務有界分工，避免重複工作與相互覆寫。本次規則更新沒有啟動代理。
3. **額外購買才是費用邊界。** 不購買、加購、升級、啟用試用、自動付費續用或訂閱外另行計費API／託管服務。不新增付款方式、不改帳務或提高消費上限。遇到明確額外收費或額度不足提示，不付款續用，完成其他可做的工作。
4. **新服務單獨處理。** 若要引入一個全新服務，且無法判斷是否另計費，先不用該新服務，採既有或免費替代；不要把這個疑問擴大成禁止正常Git、測試、內建工具或整個任務。
5. **不重複查帳。** 沿用使用者的付款方式／API key說明及已核對的官方政策。只有服務、方案或操作出現實際費用提示等新情況時，才核對對應項目。不搜尋、索取或列印任何密鑰來證明「沒有key」。這些說明是授權與執行依據，不是整個帳戶未來永遠零扣款的保證。
6. **以有效工作提高速度。** 批次執行獨立查詢，重用已驗證的設定、來源manifest、測試結果與恢復包。只有新程式變更、失敗或具體剩餘風險才增加測試；純文件／授權更新不重跑全套、不重建已驗證交付ZIP。不進行無必要的反覆版本查詢、全庫展開或費用確認。
7. **保存與品質持續有效。** 正常提交、推送及GitHub精確讀回直接執行；不強推、不合併受保護main、不部署。checkpoint、程序隔離、來源版本、穩定ID、隱私與已延後資格不放寬；不得為速度偽造驗收、刷新問題基準或把未知項目當PASS。

## 費用證據與實際結果

GitHub官方無有效付款方式時Actions額度用完停止的固定版本引文與hash，見[authorization.json](../dev/pre_download_audit/github-persistence-20261021/authorization.json)。正常推送已實際成功；獨立Git讀回及標準checkpoint收據見STATE。GitHub REST API的Forbidden屬存取限制，使用已可用的原生Git完成保存，沒有繞過網路政策或另開付費資源。
