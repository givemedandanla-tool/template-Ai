## 1. 推測的實際需求

1. 使用者遇到排版／字型／Logo／來源／標記／品質問題時，需要知道「哪個作品、尺寸、人物欄位出了什麼問題、哪些已證實、下一步在哪裡處理」。
2. 關閉畫面或交接給其他人、工程師、GPT後，仍要保留同一次判定與必要數值；截圖不能可靠保留版本、問題分母、未完成搜尋及未知事項。
3. 交接不應要求上傳客戶原稿、電話、公司Logo或字型。收到報告的人可以理解問題，但不應由報告取得修改主檔、發布模板或放行輸出的能力。
4. 報告修復後是歷史證據，不能持續代表最新結果；返回原問題須核對既有資料版本，不能按相同顯示名稱猜測人物。

以上是由現有流程推導的建議，不代表已證實每位使用者都需要獨立報告；建議把報告設為**按需產生的交接工具**，不新增日常強制步驟。

## 3. R1建議：一份交接包、兩種閱讀方式

建議第一版按需輸出一份 `DIAGNOSTIC_<日期>_<隨機代號>.zip`，內含：

- `report.html`：給人閱讀的離線摘要、問題表、必要幾何示意；無JavaScript、無遠端資源、無追蹤碼。
- `report.json`：同一份安全快照的結構化內容，供GPT／其他程式讀取；JSON使用schema_version與固定列舉，不藏未出現在檢視畫面的資料。
- `manifest.json`：固定schema／產生器版本、兩個檔案的大小與SHA-256，供損壞檢查。這是完整性檢查，**不是作者簽章、來源可信或內容正確保證**。

只交接一個ZIP可避免HTML與JSON版本混用；軟體內提供「開啟報告」直接閱讀，外部收件人解壓後以瀏覽器或GPT讀取。獨立PDF可列後續選用，不納入首版；PDF不能取代機器資料。ZIP僅封裝報告，不自動加入.ai、圖片、字型、模型或DB。

### 建議內容

| 區塊 | 內容 |
| --- | --- |
| 報告身分 | 隨機報告ID、格式／app版本、產製時間、歷史快照／非正式標示 |
| 檢查範圍 | 本次實際選取作品／候選／尺寸，以報告內代號表示；來源檔、作品、欄位分母分開 |
| 判定與證據 | 預估風險、已驗證的特定約束違反、證據不足、未檢查／過期；附各自證據範圍 |
| 可核實數值 | 固定字級、框寬／實測字寬、允許／所需X比例、必要座標／尺寸；無可用字型時寬度UNKNOWN，不填0冒充量測 |
| 搜尋與工作狀態 | 實際已計算／候選總數、未開始／取消／失敗、是否完整遍歷已知集合；未知分母就是未知 |
| 問題清單 | issue code、欄位類型、人物／公司代號、局部位置、合法修正方向；必要時指出無法可靠定位 |
| 版本與不足 | 本次資料／模板／字型／Logo／規則依賴是否已核實；缺模型或未執行推論照實標示；實體印刷未驗證 |
| 操作提示 | 原軟體中的修正入口、修正後重新驗證；報告本身不提供自動修復或放行 |

狀態必須分軸：候選數位輸出、來源健康、模型品質、實體印刷各有原判定；不能匯成一個誤導的綠色PASS。某候選硬性失敗不等於全部模板無解，沒有候選不等於所有矩形排版不可解。當前程式沒有全域無解證明時，報告不得自行生成「全域已驗證無解」。

快照與畫面使用同一份原始驗證結果。新增結構化issue是在原驗證器建立code／typed參數／exact target，並保留舊GUI字串相容；不是第二套驗證器。尚未結構化的錯誤保留本機詳情，分享版用「未分類錯誤，需本機核對」，不能猜測個資或位置。

## 4. R2建議：本機產生、安全交接、版本有效才定位

建議GUI流程：

`現有問題面板 → 產生診斷報告 → 核對範圍／版本 → 預覽安全內容 → 選本機位置 → 完整寫檔與校驗 → 使用者自行交接`

- 入口只加在既有輸入、候選與訓練品質面板；共用一個報告建立器／閱讀器。
- 預設「安全交接版」，只本機保存，不自動上傳GitHub／雲端、寄信或傳訊。工程開發用的GitHub工作紀錄與本產品報告是不同資料流。
- 產製前列明實際範圍，不預設打包整庫。各尺寸仍分項，不把單尺寸合格套到其餘尺寸。
- 預設文件名只含報告代號／時間，不使用客戶編號、姓名、公司或來源原名。撞名要求更名，不覆寫成功檔；取消／磁碟滿／權限錯誤不回報成功。
- 同一安全快照產HTML／JSON，整個ZIP在同目錄暫存、校驗後排他發布；失敗清理本次暫存，不動原稿及既有報告。既有磁碟不支援安全發布時明確失敗，不退回危險覆寫。
- 原資料在預覽與確認之間改變：取消此快照建立並提示重新產生；歷史已保存報告保持原樣，不能靜默改成當前結果。

### 安全交接版的資料白名單

第一版只輸出問題類型、必要數值、範圍、匿名代號、未驗證項與核准的靜態說明。不輸出原始姓名／電話／Email／LINE／IG／地址／客戶編號、公司名稱、原稿與Logo、原始檔名／路徑、自由文字備註、例外stack trace、DB／環境dump或工作lease／密碼／金鑰。

- 使用每份報告新產的「人物A／公司A／來源A／候選A」代號；不以相同字串推測共用身分，也不跨報告形成穩定客戶追蹤碼。
- 分享包不含本機source/work/slot/customer UUID、原稿內容SHA及私有定位索引。這些參照留在本機版本核對；避免以hash冒充已去識別。
- 自由文字錯誤不能原封不動帶出。以code＋數值型參數生成審核過的文案；未知code或未核准欄位不輸出，明示交接版省略／需本機核對。**只靠正則遮電話或刪token欄位不足以聲稱去識別完成。**
- 第一版不附原畫面截圖、原稿縮圖、PDF／SVG字層或圖片。需要位置示意時，只畫經核對的矩形與匿名欄位類型；無可靠幾何則省略，不能拿真實Logo／文字冒充安全示意。
- HTML與JSON、檔名、manifest、ZIP條目及所有中介資料一起檢查。使用者預覽的必須是實際將寫出的安全內容。
- 完整個資／原圖除錯包不在首版範圍；UI048完成前仍只用合成／合法去識別資料驗收，不能把此報告功能宣稱為正式個資權限系統。

### 本機定位與保存期限（建議預設，待採納）

共享ZIP與本機私有定位資料分離。建議在既有Library的受控本機目錄保存最小索引：隨機report_id → 既有entity ID、revision、原始依賴指紋；不複製人物資料，不另建訂單／永久案件DB，不把私有索引加入分享ZIP。

索引建議預設7天到期刪除，於啟動／開啟報告時清理，並可立即清除；程式關閉期間不承諾準時清理，邏輯刪除不宣稱磁碟鑑識不可恢復。使用者明確保存的安全報告檔不自動刪除。7天是本提案的產品預設，尚非使用者已定案或法定留存期限。

同一Library開啟報告時，只有索引存在、依賴可取得且exact版本相符，才啟用「定位原問題」。若索引已清除、資料已變更、來源失聯、在另一電腦或不同Library：仍可唯讀閱讀歷史報告，清楚提示不可定位／版本過期，不用代號或同名強行對應別人。返回當前問題與重新驗證仍使用原畫布／Gate，不把報告中的歷史PASS寫入DB。需要搬移原始資料時另走備份／來源重連，不把報告做成備份還原包。

### 開啟外部報告

第一版只接受本工具定義的schema。驗證manifest、JSON／HTML允許欄位與內容相符、限制大小／筆數；manifest校驗無法證明可信作者。建議上限2MiB、最多2000個問題，可先收斂更小範圍；這是保守實作預算，需測試，不宣稱已在VivoBook實測。

拒絕絕對路徑、`..`、重複ZIP條目、symlink、額外附件、壓縮炸彈與外部連線／腳本。軟體內閱讀優先從已驗證JSON重建純靜態畫面，不執行外來HTML；原始HTML內容須escape並採限制性CSP。來自別人的報告不自動建立本機定位映射、不載入模型／字型、不更新主檔或觸發生成／訓練。

## 5. 擬議驗收（全部待開發／待測）

1. 同一快照的GUI／HTML／JSON在問題code、嚴重度、尺寸、證據範圍與版本一致，報告不得重新猜測判定。
2. 固定字級適配失敗、缺字型／無法量測、缺Logo、無模板、部分搜尋、取消與來源過期分別呈現；不出現無證據的全域無解／假PASS。
3. 來源、人物／公司同名或同電話仍按既有exact實體分離；報告內代號不造成跨人定位。
4. 實際編碼的多個尺寸只有合格尺寸保留原Gate；報告生成／閱讀／返回不改任何正式輸出可用性。
5. 注入合成姓名／電話／Email／路徑／備註／例外訊息及lease值，檢查整個ZIP和解壓內容、HTML、JSON、manifest、檔名與中介資料，不得殘留禁止值；未知欄位拒絕帶出。
6. 本機索引存在且全部版本相符才定位；修改資料／重連來源／變更模板字型Logo／換Library／索引到期時不誤定位，仍能閱讀歷史內容。
7. 預覽後版本異動、取消、磁碟滿、權限失敗與撞名保持真實失敗；原稿、舊報告與成功成品不受損。
8. 無可用原稿、字型或候選時仍可生成安全的「缺證據」文字報告，不強制先渲染原稿／原字型而卡死。
9. 非法schema、額外ZIP條目、路徑穿越、重複條目、symlink、超額／高壓縮檔、腳本與外部URL不執行／不解壓到任意位置。
10. 上限／截斷情況明示真實已檢查分母及未納入項，不默默刪失敗資料；GUI背景任務失敗後恢復控制並保留既有工作。
11. 實際Qt流程從原問題面板建立→預覽→取消／保存→離線閱讀→合法定位／過期拒絕均可操作；不用文件或schema代替介面實作。
12. 新source固定GitHub後完整相關回歸、來源未異動、逐條證據／功能清單／checkpoint／交接/API讀回，才可標R1/R2完成；不自動打包EXE、不合併main。

## 6. 建議實作順序與決策邊界

1. **共用診斷快照**：先建立typed issue／只讀snapshot adapters與一致性／過期測試；重用已有驗證器，不另訓練模型。
2. **R1安全內容與封裝**：同一白名單模型產靜態HTML／JSON／manifest／ZIP，與缺證據情境一起驗收。
3. **R2流程與定位**：既有面板入口、實際預覽／本機安全寫入、最小私有索引與期限、外來報告只讀及原定位／Gate保護。
4. **整合證據與保存**：真Qt、敏感值注入、檔案失敗／版本競爭、必要回歸及GitHub checkpoint。

本提案建議採納的具體選擇：**按需交接報告、ZIP內HTML+JSON+manifest、安全交接版預設、原圖／個資包不納首版、既有面板入口、本機保存／使用者自行分享、私有定位索引7天、正式輸出與學習Gate不變**。PDF與包含個資的完整除錯包可另列後續，不擴大本次首版。

採納後先將R1/R2從「缺規格受阻」改為已規劃／待實作並保存BEGIN與具體驗收，再開發；**解除受阻不等於已實作或已驗收**。本輪僅設計提案，原要求狀態仍70部分／2受阻／3延後，CORE81／GOV7不變。原UI066歷史決策與未決內容保留，不寫成使用者已核准。
