# 獨立可搜尋教學與功能知識庫方案

狀態：**DRAFT_FOR_DISCUSSION／供參考，尚未採用或實作**。日期：2026-10-21。

使用者要求在軟體本體之外，建立可用關鍵字找到教學與功能說明的資料庫，並參考成熟軟體、優秀開源、心理學與設計學。本方案補充既有 `TUTORIAL_AND_PANEL_SIMPLIFICATION_PROPOSAL.md`；不取代其軟體內教學，不把兩份草案當已核准功能。範圍是獨立說明中心，不是對外客戶的排版網站或手機產品。

## 1. 推薦方案：一份內容，兩種入口，依版本交付

建立 **「Template AI 說明中心」**：軟體關閉時也能獨立開啟；使用者可以搜尋、瀏覽分類、收藏文章或查看問題解法。同一來源內容也提供軟體內的短提示、教學及「查看完整說明」連結。

優先提供可下載的離線HTML說明包，教材、圖片及搜尋索引都在本機。目標是解壓後雙擊首頁便可查詢，不要求使用者安裝Python、啟動伺服器或登入線上服務。這是設計目標，須通過實際瀏覽器與離線驗證才可宣稱完成。

底層採有結構的文字文件、文章中繼資料及自動產生索引；使用者不需管理SQL資料庫。知識庫與客戶資料庫、私人作品及訓練模型分離；搜尋只處理公開教學內容，不讀取或索引客戶庫。

## 4. 使用者如何找到內容

首頁以搜尋框為主：「想做什麼？輸入操作、問題或錯誤碼」。下方提供第一次使用、填資料與排版、匯入與學習、管理版面、遇到問題、版本與維護等目的入口；分類是可測試的設計選擇，不是心理學規定的固定數量。

核心內容分四種，另有排查與版本入口：

| 直白名稱 | 用途 | template-Ai例子 |
| --- | --- | --- |
| 帶你學一次 | 安全範例、觀察成果、練習及回饋 | 用合成資料完成第一份稿件。 |
| 現在要怎麼做 | 已有目標，直接找可靠步驟 | 加一個人、交換電話位置、換公司圖片。 |
| 功能怎麼用 | 查用途、前提、參數、限制與狀態 | 尺寸與畫面縮放差在哪裡；共享資料會影響誰。 |
| 原理與原因 | 理解規則及設計理由 | 家族為何能承接不同輸入；更正後為何要重新確認。 |
| 遇到問題 | 用現象／錯誤碼找到可恢復的行動 | 缺字型、找不到版面、預覽過期、無法啟動。 |
| 版本與維護 | 查此版本的變更、相容性與已知限制 | 更新、備份、回復及安全報告。 |

排查文章仍以問題解決為目的；FAQ可作短入口清單，連到正式文章，避免另複製一套回答。功能總覽顯示可以做什麼、前提及目前限制，不直接把開發父題編號當新人導覽。

搜尋結果至少顯示：明確標題、一句解決什麼、文章類型、適用版本及必要限制；點進去直接到相關段落。例：

> 搜尋：電話換位置
>
> **調整電話與手機的位置｜操作步驟**
> 查看如何拖動、何時需重新確認，以及不能移動時如何處理。
> 頁面及結果會標示實際適用版本。

此為呈現示例，非目前已建好的搜尋結果。

## 5. 中文關鍵字搜尋設計

首版以可在本機驗證的關鍵字、中文斷詞、任務別名及相關詞為主；原始索引與查詢處理須一致。普通人不必輸入核心術語。

- 支援繁體主要用語及常見繁簡／寫法差異，例如拖動／拖曳、模板／模版、共用／共享、Logo／公司圖片。別名按任務及上下文維護，不把所有近義詞無條件視為同一功能。
- 區分「手機號碼」與「手機版軟體」；後者應找到明確的支援範圍說明，不能返回不存在的手機版操作步驟。
- 專業詞也可查，例如家族、ScaleX、輸出Gate；一般區先顯示人話解釋與可用操作，再連專業詳情，不重新加入已撤回的字級／字寬控制。
- 英文大小寫、全半形與標點正規化只用於教學搜尋。NFKC不會做繁簡轉換；繁簡須另採經核對的詞表／轉換能力。這些處理不能改到客戶輸入資料。
- 先選適用版本及內容範圍，再排名；精確標題、專用錯誤碼與任務別名優先，之後才用分詞全文及受控近似匹配。短中文字詞近似不可過度放寬。
- 無結果時保留查詢，提供相關任務、替代用語及求助入口，不捏造答案。預設不記錄原始查詢；研究記錄另採明示自願、本地及最少資料。

Material的公開程式有Jieba中文索引處理，但這不證明所有中文查詢已適用。首輪須驗證查詢端與索引端一致，含不帶空白的中文句子、專用詞及繁簡差異。若內建不足，補可散佈詞典或改接適配器；不為省事改成付費搜尋或上傳服務。

## 6. 每篇文章應包含什麼

常用文章先回答「這篇能幫你做什麼」，再給目前必要內容；背景及技術詳情可深入閱讀。重要限制不能只藏在展開區。

操作文章的固定結構：目標、適用版本、開始前要有什麼、實際步驟、完成後應看見什麼、常見卡點／復原，以及相關功能。步驟中的按鈕名稱與實際畫面一致，圖片放在對應步驟附近，不把讀者推向另一份長文件自行找答案。

功能參考另說明用途、資料影響、規則／限制、是否可逆，以及關聯操作。真實作品品質、Windows硬體、字型來源與實印資格仍須忠實標示；文章已校對不代表該產品資格已取得。

必要內容欄位可包括：

| 欄位 | 目的 |
| --- | --- |
| 穩定article_id、標題、類型、別名、標籤 | 可靠連結、分類與搜尋，不因改標題就失聯。 |
| 適用軟體版本／來源提交、最後核對版本 | 防止把舊按鈕或未發佈功能教給當前使用者。 |
| 內容審閱狀態 | 草稿／已核對／歷史，控制哪些可發布與索引。 |
| 功能可用狀態與驗證範圍 | 與內容審閱分開：已實作、受限、待驗證、規劃／延後。 |
| 前置條件、預期結果、限制、復原及相關文章 | 讓人能完成或安全恢復，不只是看定義。 |
| 動作／教學ID、技術依據、圖片來源版本 | 對接軟體內說明、維護及必要的專業查證。 |

索引採明確使用者內容清單，不掃整個Git倉庫、歷史日誌、草案、客戶資料庫或私人檔案。規劃中的操作教學不混入預設可操作結果；核對過的「目前未支援」說明則可被搜尋，避免讓人誤以為查不到就是自己不會用。

## 7. 與軟體內教學及維護共用

建立例如docs/help的使用者內容來源，將固定事實、完整步驟、短提示及相關動作以同一article_id管理。短提示與完整文章可有不同長度，但事實、限制及適用版本一致，不手工複製兩套失去關聯的答案。

軟體「這是什麼／看完整教學」可開啟匹配版本的本地文章。錯誤畫面以明確文章ID定位解法，而不是讓使用者重新猜關鍵字；知識庫關掉軟體仍能用。知識庫返回軟體的自動啟動／深連結不是首版必要前提，不能依賴尚不存在的通訊協定或註冊機制。

內容採文件即程式碼流程：草稿 → 核對當前功能／規格／操作 → 建立索引與離線包 → 驗證 → 發佈及遠端讀回。教材有影響的程式變更應一併更新文章／圖片與對應測試；不能只換版本號就宣稱舊教學已更新。

操作說明、重要限制及功能狀態由核准規則、實際程式和有效證據支持；不從過期聊天或模型猜測產生新事實。舊決策、原驗證報告保持歷史，不改成新版本宣稱。

## 8. 離線、版本與交付方式

優先以免費MkDocs／Material生成離線包，保留授權並固定工具與依賴。它們是開發／文件建置工具，不放進產品的日常執行依賴。Material目前可讀取的MIT程式包含離線與中文相關能力；不使用未核實免費資格的功能。

要分別驗證「可打開網頁」及「從file://真的可搜尋」。官方文件指出file://不能依賴fetch的功能，預設的動態版本切換等功能需停用或改為本地靜態連結。檢查過的離線插件還會加入未固定版本的CDN shim；因此必須將需要的腳本、字型、圖片、CSS與索引固定來源、核對授權及hash並本地封裝。不能宣稱只啟用offline就零網路依賴。

首版採單一軟體版本的離線說明包，首頁與文章標清版本；不依賴線上版本JSON或額外搜尋伺服器。若含多版本，索引及連結需真正分離，未下載的舊版明說缺少，不自動取網路內容。

依現有發佈政策，軟體版號維持單一使用者識別；教材另有自動管理的修訂識別。可規劃如 `TemplateAI-Help-v0.2.0-beta.1-r1.zip`，更正教材另發r2，不覆蓋已發布檔。此為命名建議，尚未發佈該軟體或教材版本。

教材獨立修訂不必強迫改軟體版號，但須標適用軟體及來源。若舊Release已不可變，使用獨立文件發行保存新包，不替換舊附件或tag。此教材修訂策略是本方案待採用項目，不在本輪改寫已採用版本政策。

GitHub保存來源、修訂及公開合成證據；離線包供本地閱讀。PDF可補充快速卡／列印手冊，主要查找仍用可搜尋HTML。GitHub Pages或其他線上站不是首版必要條件，本輪不啟用託管平台、服務或CI。

## 9. 先做哪些內容

先以高頻問題整理第一批文章，再擴成完整功能覆蓋；不是把全部開發文件搬進去。建議優先：

1. 第一次準備、如何確認軟體版本、程式打不開。
2. 填人物、公司、共享聯絡資料與多筆資料；加入第二個人。
3. 產稿、預覽、拖動與選單式位置調整、更正後重新確認。
4. 公司圖片／Logo、成品尺寸與畫面縮放。
5. 已確認稿、重訂與舊版本保護。
6. 缺字型、容量未知、沒有合法版面、無法輸出與安全報告。
7. 匯入作品、模板與家族的差異、批次與單一版面管理。
8. 學習、驗證、啟用的用途及邊界；備份、恢復、更新與回退。

第一份安全練習文章可與上一份教學方案共用，但新的一鍵練習尚未實作，不能提前發布成現有按鈕教學。先盤點現有入口可教哪些、哪些須等待功能。

每個已宣稱可用的重要功能要能連到說明或明示缺口；內容優先序不新增／重編原AI8工作包或75父題，也不改目前完成數。

## 10. 實施與驗收

1. **內容盤點與資料格式。** 對現有指南去重、分類、核對版本；選一批文章，定義模板、ID、詞彙及可發布清單，連回既有功能。
2. **最小離線搜尋實證。** 以少量真實教材頁驗證繁中、別名、file://、本地資源及版本隔離，確認免費選型能達成；這一階段尚未執行。
3. **建置及教學接線。** 擴充內容、產生索引／離線包，對接軟體內說明與錯誤文章；按已採用發佈流程交付並讀回。
4. **使用者查找實測及維護。** 觀察沒參與開發的人能否用自己的詞找到並完成任務，再修標題、詞彙、分類或內容，並保存已知缺口。

建立人工預先標定的搜尋案例，不拿搜尋引擎自己給的答案當正解。涵蓋日常詞、專業詞、繁簡、無空白中文句、大小寫、專用錯誤碼、無結果、版本衝突及未實作功能。例：電話換位置、共同電話、第二個人、logo、字型找不到、為何不能輸出、手機版。

檢查正確文章是否出現在前幾名、是否選對版本及能否解決任務；另量測首次載入大小及實際搜尋時間，再依本地硬體設定合理目標，不先保證所有Windows電腦的速度。

工程驗收含：文章／片段連結、資源與授權、適用版本、草稿／歷史索引排除、無私人資料、無自動對外請求、軟體關閉仍可用、鍵盤及小畫面閱讀。全新解壓目錄與支援瀏覽器要驗證；Windows file://及新手查找需要實機證據，不能只靠建置成功或Linux檔案檢查冒稱通過。

目前只完成研究、盤點與設計，未建置網站或搜尋索引、未安裝套件、未做檢索／使用者驗收、未改GUI或發布教材。兩份教學草案及本方案待後續討論採用；原已核准發佈規則與所有產品資格保持原狀。
