# 直觀桌面製作面板：研究與接續方案

白話摘要：讓新人先填資料、看到完整稿件，再直接改內容或調位置；平常不需要理解模型、家族、來源證據或印前代碼。共用一個製作工作區，專業學習／模板工具另外按需打開。這次已接入設計 skill、Qt 視覺工具並驗證概念稿；下列全面視覺重整是接續設計方案，不是已交付的新正式面板。

## 已確認要求與現有能力

- 依訪談與本輪 INPUT_LEARNING_INTERFACE_MAP.md，簡易表格、人物卡片、公司／共用資料、重訂、Logo、尺寸都需接同一輸入圖與稿件版本。
- 內部同仁是目前使用者；外部客人網頁／手機延後。兩種角色未來共用核心與製作元件，不先建立兩套重複輸入流程。
- 相對位置可調，拖動不能任意改掉無關關係；規則允許的欄位大小、字級、字寬、切齊與分散由核心求解。客人沒有這些細部控制。
- 已確認稿與固定舊版保留原版，改內容或位置使舊確認失效；同輸入、同版本與意圖有穩定預設，不隨機換稿。
- 容量引導來自有條件的訓練／驗證結果。未知不等於無解，工程儲存上限不冒充學習容量；不在面板自行發明字數或欄位上限。
- 目前實作入口：MainWindow／DesignLearningDialog／DesignSessions／production_bridge、input_graph_dialog、production_report。原有專業家族與批次工具保留，避免重做資料層。

## 研究依據及取捨

固定提交、檔案與讀取 hash 見 [GUI_RESEARCH_SOURCES_20261020.json](GUI_RESEARCH_SOURCES_20261020.json)。實際閱讀的是公開設計系統／原始碼，未宣稱操作商業付費帳號。

| Penpot | options.cljs 依單選／多選／操作狀態切換情境面板 | 選到資料後才出現相關工具；模板編輯與日常製作分層 | 通用向量編輯器所有尺寸／文字／圖形控制 |

不是照抄某個軟體的面板。Template AI 的製作稿件已受學習規則、固定尺寸、版本及輸出資格約束，必須在這些條件下簡化操作。

## 共用製作工作區

| 區域 | 新人看到的操作 | 重用的現有能力 |
| --- | --- | --- |
| 左側「填寫資料」 | 人物卡片、公司與共用資料、加一項資料、選圖片、尺寸；進階內容收合 | InputGraph 的身份／歸屬／共享；舊表格保留為熟手選項，不另建資料契約 |
| 中央「檢查與調整」 | 完整稿件為主；點選看所屬資料、拖動改相對位置；復原／重做；返回修改內容 | 同一 DesignSession 的資料修訂、相對意圖、候選與真實預覽；不使用概念稿的示例卡片作正式結果 |
| 右側「目前狀況」 | 現在能做什麼、哪筆資料需要處理、下一步；可收合 | 同份結果的容量建議、錯誤及 production_report；保留原詳情 |
| 底部主動作 | 依狀態顯示「產生稿件／更新稿件／確認這份稿／儲存輸出」 | 背景求解、取消、版次核對、確認與既有 PNG/PDF/JPG 輸出 |
| 「模板與學習」工作區 | 由有需要的內部同仁進入，保留專業工具及來源審查 | 既有16項模板／家族編輯工具與訓練管理；不把工具都堆入製作面板 |

未來外部角色可共用製作元件，須由核心權限限制專業命令，不能只隱藏按鈕。這不提前開發對外服務。

## 狀態與回復契約

| 狀態 | 白話說法／主動作 | 保護與回復 |
| --- | --- | --- |
| 尚無初稿 | 「填好資料後就能產生稿件」／產生稿件 | 保留輸入，不要求先挑懂模型或家族 |
| 正在處理 | 「正在尋找合適版面」／停止這次排版 | 顯示可理解的進度；停止後資料仍在，晚到結果不能覆寫 |
| 有可預覽結果 | 「可以檢查內容與調整位置」／確認這份稿 | 點選與拖動都走核心意圖；若需換版面要可見地解釋 |
| 資料或位置已改 | 「資料已修改，請更新稿件」／更新稿件 | 不把舊畫面當新結果或保留舊確認；不要使用 STALE／CAS 作主要訊息 |
| 已確認 | 「這份稿件已確認」／儲存輸出 | 輸出核對同份資料與版本；印前未合格不能用確認動作繞過 |
| 遇到問題 | 「哪筆資料、影響、怎麼處理」／回到問題或重新嘗試 | 保留文字與原稿、就近錯誤；詳情可另存安全報告 |
| 重訂沿用 | 「沿用已確認稿」／檢查並沿用 | 查找既有確切稿件，未明確改稿不因新模型重排 |

保留並重用既有「欄位／在左側、右側、上方、下方／參考欄位」選單與「調整兩欄相對位置」按鈕，它們已與拖動呼叫同一核心相對關係命令。既有GUI回歸也實際走過選單修改；不重做第二套位置引擎。新面板應改善這個替代操作的可發現性與鍵盤焦點，另做實際Windows／新手驗收，不把現有Qt選單當成已取得完整無障礙資格。有衝突時保留原稿並說明原因，不用紅框代替解釋。

## 視覺與語言規則

- 安靜的淺色工作面、深色正文、單一藍色主動作、統一圓角／間距；4／8 的間距節奏只屬 GUI 顯示單位，絕不換算進成品欄位或印刷字級。
- 概念稿採系統已安裝中文字型。介面正常文字對比至少4.5:1、明顯鍵盤焦點、標籤與輸入對應；縮放、長中文、縮小視窗須另驗證。
- 操作不要只有圖示或專業縮寫。常用詞：「人物」「公司」「共用聯絡資料」「其他版面」「更新稿件」「輸出前檢查」「詳細原因」。穩定ID、weights digest、ROOT、Gate 留在專業詳情。
- 重要修復指引直接顯示，補充知識再展開。主要動作在同一位置隨狀態換名稱，不同時出現數個同等醒目的產生／確認／輸出按鈕。
- 採用資料後的版本與確認狀態必須清楚；視覺美化不能改變身份、欄位歸屬、共享或 Logo 綁定。

## 報告兩層結構

先顯示固定三欄：「發生什麼」「影響什麼」「接下來怎麼做」。例：「這次位置調整無法符合規則；資料與原稿仍保留；請復原這次調整或查看哪兩項資料衝突。」

詳情保留錯誤碼、匿名欄位量測、資料／排版版次、模型／權重／策略版本、檢查結果及附件hash。摘要不是另一個核准來源；UNKNOWN 不能改寫成合格或無解。分享報告遵守既有 allowlist，不把私人原文、來源路徑、字型檔或資料庫打包上傳。

已實作的 production_report 與安全診斷 HTML 提供摘要基礎。全面統一所有歷史報表、逐項人工編寫錯誤字典與可直接跳回欄位的摘要連結，列為後續視覺重整工作，不能把通用 fallback 說成每種錯誤都已有專用解釋。

## 接續落地順序與驗收

1. 以本輪完整接線回歸為基準，先做共用製作工作區；重用 bridge/session API，不搬寫核心。
2. 連接實際人物／共用資料元件、現有真實預覽及拖動；保留熟手表格入口與固定／已確認稿版本。
3. 整合狀態主動作、問題側欄、復原／重做、可取消進度與兩層報告，保留並改善既有相對位置選單的可發現性與鍵盤焦點。
4. 沿用既有核心測試，增加必要的真實視窗回歸；測試長中文、輸入法、縮放、視窗大小、無模型／容量未知、Logo／字型缺失、取消、重啟、重訂、輸出前阻擋。
5. 新手任務驗收：不口頭教學完成一人名片、多人及共用資料、修正聯絡資料、交換相容欄位、沿用重訂與處理一個可修復錯誤。記錄完成率、求助次數、錯誤與恢復路徑，再訂合理時間目標；目前**沒有真人新手可用性結果**。

每段保持可回復 checkpoint／GitHub 讀回。設計概念稿、工具 smoke、正式軟體回歸及真實 Windows／印刷資格分開記錄。這份方案不新增原AI8包／50條或虛增已完成數。
