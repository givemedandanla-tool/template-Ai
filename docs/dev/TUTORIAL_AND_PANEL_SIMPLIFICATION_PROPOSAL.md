# 教學機制與面板簡化方案

本輪使用者要求參考成熟軟體、優秀GitHub專案、心理學及設計學，設計教學機制與規則。此文件保存研究與方案；不新增GUI功能、不改現有規則或完成資格，不代表教學或新手實測已通過。範圍為既有PySide6桌面本體，網頁／手機維持延後。

## 1. 建議方案：一套面板，按任務呈現，邊做邊學

降低複雜度與提供教學要一起處理。教學圍繞使用者要完成的工作，而不是逐顆介紹所有按鈕。保留目前同一輸入圖、同一製作核心與同一套面板；提示可關閉、重開、暫停與接續。熟練者不必持續看新手說明。

不另做新手／熟手兩份產品流程或模型。練習有獨立本地資料空間，但呼叫相同服務與規則；這是資料隔離，不是另一套排版引擎。

## 3. 研究怎樣用，哪些不直接搬

固定來源與閱讀範圍見 `TUTORIAL_AND_PANEL_SIMPLIFICATION_RESEARCH.json`。

| 參照 | 可採用思路 | 本專案的取捨與限制 |
| --- | --- | --- |
| Microsoft VS Code Walkthroughs | 少量任務步驟、每步有動詞操作、圖與當前任務相關 | 不做龐大首次開機導覽；本體完成判定比「按過命令」嚴格，須核對真正業務結果。 |
| Microsoft VS Code Notifications | 就地呈現進度、合併重複通知、只在有影響及可採取行動時打斷 | 教學可不再提示，但核心阻擋與必要確認不能因此解除；不把上游通知偏好直接當本體的業務權限。 |
| Microsoft Fluent TeachingPopover | 緊靠當前控制項的短提示、明確可關閉與深入說明入口 | 參照互動層級，以Qt實作；不導入React，不複製示例的線上圖片依賴。 |
| Carpentries講師培訓 | 管理認知負荷、引導練習、減少專家盲點、用一致名詞、回饋後實際改進 | 教材是教學情境，轉成軟體設計仍要實測；不把記憶容量數字當按鈕上限。 |
| Mayer與Moreno（2003） | 使用者可控制的分段、移除無關資訊、訊號提示與位置對應 | 原研究是多媒體教學；本方案借用原理，不宣稱其效果量能直接套到本軟體或保證學習速度。 |

設計上採用視覺層級、接近性分組、一致命名、可見狀態及漸進揭露。只隱藏按鈕未必更好；必要功能的可找到程度也須驗證。教材不靠動畫、裝飾、強制影片或「完成率」取代任務能力。

## 4. 先把面板整理成能看懂的工作

沿用現有「排版與輸出／匯入與學習／模板與圖片」三工作區，不把它們當全新功能重做。預設留在目前工作或製作區；由目的進入另一工作區。

| 層級 | 平常呈現 | 規則 |
| --- | --- | --- |
| 常用操作 | 填寫資料、稿件預覽、調整位置、當前主要動作 | 每個狀態有一個突出的建議動作；必要次要動作仍可找到，沒有僵硬的按鈕數上限。 |
| 當前協助 | 現在做到哪裡、下一步、與當前操作相關的提示 | 一個短摘要，說明操作會造成什麼；不常駐多段同義提醒。 |
| 其他選項 | 舊表格、其他固定版面、專業模板／家族工具 | 漸進展開，保持原能力與入口可找；不另建資料契約。 |
| 救援入口 | 復原／重做、接續工作、問題與報告、備份 | 位置及名稱穩定；暫停／停止在背景工作進行時可及，不能為美化而藏掉。 |

教學開啟時可出現可收起的提示卡。寬畫面可放側邊；小畫面放在任務附近或下方，不能擠掉主要稿件。提示與業務確認視窗分開：關閉教學不會取消必要的共享資料或輸出確認。

拖動要保持容易發現；保留現有選單式位置調整作為鍵盤等效操作。相對位置可調，字級、字寬、欄位大小、切齊及分散仍由規則決定，不新增已撤回的客戶細部控制。專業模板編輯保留原核准範圍。

## 5. 五層教學，由少到多

### A. 每個狀態都有短提示

平常不用先開教學，畫面就能回答：現在是什麼狀態？下一步能做什麼？操作後會發生什麼？例如：

> 稿件已更新，請檢查內容與位置。調整位置後需要重新確認。
>
> 主要動作：確認這份預覽稿　　其他：修改資料／調整位置／教我做一次

這些是依狀態選用的文案示例，不是已接好的新按鈕。容量未知、找不到合法版面、資料已改與正在計算須有不同說法，不能用同一個「失敗」含混帶過。

### B. 在需要的地方說明

控制項旁有可點擊、可用鍵盤開啟的短說明；重要資訊直接可見，不只放滑鼠懸停。每份說明先說用途，再說必要注意及下一步；詳情可展開。

例如拖動說明：「拖曳可調整資料之間的位置；程式會依版面規則重新排列。內容不會因此被刪除。」必須以真實結果為準；若此次調整不合法，顯示原稿是否保留及可用復原方式。

### C. 一個安全的小任務，邊做邊學

入口叫「用範例練習」，不要求先懂模板發布或模型訓練。從可散佈的合成資料及合法字型準備環境；缺少依賴須明說，不能偽裝成功。

建議首次任務：填一位人物的資料 → 產生稿件 → 把電話放到電子郵件下方 → 更正一筆資料並重排 → 重新確認 → 保存練習預覽。任務同時展示「改內容／位置後舊確認失效」，不是只教按產稿。

示範一次 → 使用者帶提示做一次 → 用另一份範例、不提示做一次。可隨時暫停、退出、重開或重設練習；真實工作流程不強迫每次都做拖動或跑完教學。

練習採獨立本地Library／工作空間，與真實客戶庫明顯區分；仍走相同核心檢查。練習成果標為練習預覽，不自動加入正式學習資料、發布模板、啟用模型或變成印刷資格。範例環境準備亦不可透過偽造證書、放寬檢查或改寫原庫實現。

若核心要求版面先通過檢查才可試做，僅在隔離範例庫依原檢查準備可用示範，並保留練習預覽限制；不向真實庫發布或把未知來源標為已審查。

### D. 按真實任務查詢教學

使用者可找「我要加一個人」「換公司圖片」「電話與手機交換位置」「接續上次稿件」「這份為何不能輸出」。內容由本機任務目錄、同義詞及既有操作定位，不要求先知道功能名稱。

初期沿用已安裝Qt及本機檢索能力，提供穩定動作ID與情境說明。教學進階任務重用現有GuidedOperationsDialog，補目的、範例及先備概念；不重建第二套學習、容量或資格服務。

### E. 出錯時，教人回到可繼續的狀態

沿用已有的「發生什麼／影響什麼／接下來怎麼做」報告架構，補足高頻錯誤的具體說明及定位。例：缺少來源字型時說明目前哪個操作被擋住、資料是否保留、如何查看缺少資訊；不能讓新手自行猜測錯誤碼。

有可預覽結果且容量證據不足，與實際排版失敗是不同狀態。摘要及教學只能轉譯核心結果，不能把UNKNOWN改成合格或無解，不能自行允許輸出。未涵蓋錯誤要有誠實的通用回復與手動安全報告入口。

## 6. 教學本身的規則

1. **先有可辨認的目標。** 每份教學只針對一個任務；每步標明做什麼、為什麼，以及如何看出成功。
2. **完成看結果，不看點擊。** 例如產稿步驟須有當前資料修訂的有效預覽；按過按鈕或下一步不等於完成。
3. **學會與做到分開。** 教學完成記錄可以保留；當前工作改資料後仍需重排／重確認，不能因曾學過而跳過業務檢查。
4. **可退出、可接續、可重看。** 預設不每次開機強制重播；熟練者可關提示。軟體更新僅在相關操作有實質變更時提示，記錄相容版本，不任意清除全部進度。
5. **同一概念使用同一名稱。** 例如常用區顯示「相近版面」，詳情首次說明「版面家族」；不要在不同畫面無解釋地切換多個術語。保留技術詳情供專業人士核對。
6. **引導服務於畫面，不遮住工作。** 不用全螢幕強制遮罩串列；提示不擋預覽、按鈕、焦點或必要警告。縮放、鍵盤及螢幕閱讀器亦可使用，不只靠顏色或動畫。
7. **教學不能替人核准。** 點「我知道了」只關閉說明，不代表核准資料共享、字型來源、模型品質、風格、正式輸出或覆寫資料。
8. **練習與私人工作隔離。** 不覆寫真實稿、不混入訓練／驗證／封存集合，不索取私人作品上傳，不自動聯網、下載教材或上傳記錄。
9. **記錄最少且本地保存。** 必要資料為教學ID／版本／進度及顯示偏好。可用性研究的時間、求助及錯誤事件另採明示自願記錄，可刪除；不記鍵入內容、客戶值、私人路徑或背景錄影。
10. **畫面改了，教學也要核對。** 每個步驟綁定穩定動作／情境及適用軟體版本；控制項不存在時提供替代入口或標示暫不可用，不亂指位置或自動把步驟當完成。

## 8. 建議落地順序與驗收

下列是本方案的實施階段，不替代或重編原AI8工作包／75父題，不改目前完成數。

1. **先整理常用工作區。** 盤點各入口真實呼叫者，處理重複／模糊文字、主次動作與狀態一致性；先做小視窗及鍵盤走查。避免先寫長教材再替複雜畫面辯護。
2. **交付第一個練習閉環。** 完成隔離範例、當前任務提示、真實完成判定、暫停接續與恢復；帶資料更正及拖動，保留原核心檢查。
3. **補高頻任務及迭代。** 加任務查找、錯誤回復教學與進階概念說明；由未參與開發的人測，再按卡住的位置改善。

軟體檢查至少要有：提示關閉仍能完整操作；教學不改真實庫；晚到結果不能完成錯版步驟；缺版面／字型／容量未知／不合法位置各自忠實回報；退出再開與內容更新後進度一致；正常流程及所有既有關鍵保護不退化。

新手測試使用兩份不同範例：先引導一份，再獨立完成另一份；記求助、選錯入口、恢復、完成與時間，不只記點完教學。可先邀3–5位非開發者作形成性測試，逐輪改善，不能據此宣稱統計代表所有使用者。

可討論的初始驗收目標：5位測試者中至少4位無口頭協助完成第二份預覽稿；任務完成時間中位數不超過10分鐘；0真實資料改寫、0誤放行正式輸出。這些是產品假設而非心理學推導的常數，需先試測再決定是否合適。真正本地新手／Windows資格仍需實測證據。
