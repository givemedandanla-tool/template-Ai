## 研究結論與現況

採用 SemVer 的相容性與預發行標示、Keep a Changelog 的人類可讀變更紀錄、GitHub Releases 的 tag／草稿／附件交付、PyInstaller 的目標平台建置與資料夾散佈。固定版本來源與 SHA-256 見 `RELEASE_MAINTENANCE_RESEARCH.json`；參考的是公開文件／專案流程，不使用付費託管服務。

現況基線：`bad720bb1b65edc7ad118e586ba6e3a8219f7468`，分支 `dev/v0.1-first-version`。

- `template_ai/__init__.py` 與 STATE：`0.1.28`；README 的介紹仍標 `v0.1.26`。
- `tools/build_windows.ps1` 用 PyInstaller onedir，檔名固定 `TemplateAI-v0.1`；保留 Qt 動態函式庫與授權文件，方向可沿用。
- Windows workflow 只手動啟動，產物保留14天；它沒有建立 GitHub Release。因此不能把 Actions 成功／暫存附件當長期可下載發佈。
- 舊建置腳本使用單程序 `unittest discover`，尚需接到現行 Qt 程序隔離驗證；目前的 EXE 測試是啟動／截圖，未等於最新打包成品端到端驗收。
- 目前遠端只有兩個 checkpoint tag，未見產品版號 tag。這是實際 Git 查證，沒有冒稱查到 Release API 清單。
- 程式內安全報告已有軟體版本及環境資訊；完整發佈識別、來源提交與相容性資料仍需整合。資料預設位於使用者本機資料目錄，已與程式檔案分開，應保留。

## 一、只讓使用者管理一個軟體版號

建議首次 Windows 內部實測發佈採 **`v0.2.0-beta.1`**，作為累積 AI／家族／GUI 能力的新測試基線。這是建議值，本輪沒有改號。

| 標示 | 白話意思 | 增號規則 |
| --- | --- | --- |
| `v0.2.0-beta.1` | 供本地試用的第1個測試版 | 同一預定版本修正或調整後發 `beta.2`、`beta.3`。 |
| `v0.2.0-rc.1` | 功能凍結、準備正式交付的候選版 | 以修正為主；新增大功能應回到測試階段。 |
| `v0.2.0` | 這一輪已通過所聲明支援範圍的正式版本 | 不等於軟體永遠沒有問題，也不豁免原外部資格。 |
| `v0.2.1` | 修正既有功能，保留相容性 | 修正號加1；不在修正版暗帶新功能或破壞性資料變更。 |
| `v0.3.0` | 下一輪功能或重要變更 | 次版號加1、修正號歸零。 |
| `v1.0.0` 之後 | 對已宣告的功能／資料／行為相容性作正式承諾 | 相容修正加修正號；相容新增功能加次版號；破壞相容性加主版號。 |

SemVer 對 `0.x` 原本不承諾相容性。本專案另外約定：0.x 修正號也要保持既有支援契約；不相容變更必須升次版號、明示遷移及回復條件，不能當小修正偷渡。

使用者說「修正 beta.1」表示以該版本調查，不是覆寫 beta.1。若發布下一個修正版，仍在同一預定版本時使用 beta.2。已發布穩定版0.2.0的修正則以0.2.1為目標；需要本地先測時，可先發0.2.1-beta.1或rc.1，再發0.2.1。

不以日期、`final2`、`最新版`、`修正最終版`或僅 `+build` 區分可下載的不同軟體。日期與建置識別可由機器另記，不增加使用者要背的版號。

## 二、同一版號只代表一份已發布成品

- 一旦可下載，不覆蓋該版二進位附件、不移動或重用產品 tag；內容改變就用新版號。草稿未發布前可調整，但須重新固定來源並驗證候選包。
- 一個固定程式提交產生候選包；**測試哪一包，就上傳哪一包**。測試後重建、改版號或變更內嵌資訊，就必須驗證新候選包，不能沿用舊包的通過結論。
- 例如 rc.1 轉正式0.2.0，若內嵌版本跟著改變，便是新成品，需要對最終包驗證；不能只把rc檔重新命名。
- 使用既有單一版本來源生成「程式顯示、報告版本、tag、下載包名稱、發佈清單」並檢查一致性。Windows數字版本欄位採固定映射，保留完整預發行字串供查證。
- 歷史報告與歷史變更紀錄保留原版號，不全庫取代成最新號。
- Git commit 是精確程式來源；checkpoint 是開發接續記錄；兩者都不是使用者的軟體版號。資料庫、模型、規則、模板與定稿仍有各自版本，由系統管理，不要求使用者人工編號。

## 三、哪些話授權到哪一步

| 使用者用語 | 建議預設範圍 |
| --- | --- |
| 開發／修正這個問題 | 調查、必要修正、驗證、checkpoint及GitHub保存；不自動每次都打包發版。 |
| 準備發佈 | 完成固定來源、建置、測試與可審閱草稿；不對外發布。 |
| 發佈測試版到GitHub供我下載 | 授權完成建置、驗證、建立測試版Release、上傳及實際下載核對，不逐項重問例行操作。 |
| 正式發佈 | 依已採用的穩定版驗收條件執行；不能把測試版直接宣稱正式合格。 |

版本號可由Codex依採用規則決定；使用者指定號碼時先核對既有tag及待發佈登錄。若已使用或與相容性規則衝突，明確說明，不自行覆寫。

發佈前讀取最新發佈登錄、tag、已保留版號及精簡交接，避免不同對話各自宣稱不同「最新版」。不自動合併main或部署；目前開發分支可在指定且已驗證的提交上建立發佈tag。

## 四、首次 EXE 發佈流程

1. **核對來源與範圍。** 讀取AGENTS、STATE、當前工作分支及實際HEAD，核對未提交修改；選定Windows架構、測試版號、功能及已知限制。先確認Windows執行器與GitHub Release寫入／附件權限；Git push可用不等於Release API也可用。
2. **補齊一次性的發佈接線。** 統一目前版號、接上Qt程序隔離測試、加入打包成品驗證與發佈識別、確認外部Inkscape／字型等依賴如何就緒。保存已選工具與實際Windows建置環境，沿用可用免費／既有工具，不新增付費服務。
3. **固定來源再建置。** 記錄確切提交與相依版本，在Windows建立Windows程式。PyInstaller輸出與作業系統／Python／架構有關，不能把Linux產物改名為.exe。
4. **驗證實際成品。** 除來源碼回歸外，從打包資料夾啟動實際.exe，驗證輸入、產稿、預覽、拖動、更正、重新確認、允許的輸出、安全報告、暫停／重啟與保存。沿用現行規則與程序隔離，不為打包放寬無解或正式輸出Gate。檢查包內沒有私人作品／客戶庫／私人字型／訓練模型及開發工具。
5. **明示資料相容。** 新舊資料庫及模型版本可否開啟、是否需遷移、備份及回復限制必須可查；驗證不破壞舊定稿、人物歸屬與來源版本。試用使用本地資料副本，不讓測試版自動升級唯一原庫。
6. **備齊草稿附件。** 首輪建議用現有onedir方式，提供 `TemplateAI-v0.2.0-beta.1-windows-x64.zip`，內有.exe、必要函式庫、繁中快速入門與授權。解壓後執行.exe；不要只取走.exe。程式不需另外裝Python；未隨包提供的Inkscape等工具須在說明及就緒檢查中明列。
7. **發布並讀回。** GitHub Release標為Pre-release，附變更摘要、已知限制、驗證摘要、SHA256校驗及發佈清單。上傳完成後從下載連結重新取得成品，比對hash、檔名及版本，再回報可下載。必要附件未完整或校驗不符不得宣稱交付完成。EXE／ZIP放Release附件，不塞進原始碼Git歷史；Actions artifact只作暫存。
8. **交接收尾。** 記錄Release網址／tag／來源提交／實際下載包hash／驗證結果／資料相容性／已知問題／下一版待辦。標示「已發布待本機確認」；使用者實測回覆後才能標「使用者本機確認」。

既有「真實作品品質、指定Windows硬體效能、實體印刷、新手完整資格」不要求先全部補齊才提供內部beta；但必須忠實列為未驗證。測試版仍須通過其宣稱可用流程的必要成品驗證，保留輸出與資料保護。無條件放行不是測試版政策。

可使用GitHub提供的草稿／不可變發佈機制；是否啟用設定需另按現有權限及採用範圍處理。流程本身不依賴新付費功能。初始套件可能尚未有Windows程式簽章，必須如實標示，不以要求關閉防護替代查證。

## 五、修正與日後維護

- 日常開發先累積在「尚未發布」變更紀錄；到明確發版里程碑才產生新的下載版本，不為每次Git提交發版。
- 緊急修正從「實際受影響的已發佈tag」建立修正工作，避免把尚未驗證的新功能混進修正版。必要時再將修正帶回持續開發的分支，保留可追溯記錄。
- 普通錯誤採相關回歸；每次成品發佈另執行專案要求的發佈檢查。Qt維持程序隔離；需要增加執行時限時依測量及具體工作量設定，不盲目重試或放寬斷言。
- 造成資料損失、私密資料外洩、錯誤正式輸出或毀損定稿的問題優先處理，未處理前停止受影響的發佈／流程。其他已知限制可明列；未重現不能寫成已修正。
- 改模型或規則不等於可重寫舊模板與定稿。已確認稿保留所用模型／規則／字型與成果版本；新預設也不能令同一已確認訂單反覆改版。
- 程式與資料分開升級。資料格式有變更時先驗證本地備份與遷移；新版資料庫未證明能給舊版讀取時，不讓舊.exe直接開新版庫。回復可能須恢復「舊程式＋相應備份」，不是只換.exe。
- 保留舊Release及變更紀錄。問題版標示已知問題與建議替代版；嚴重問題可撤下下載，但保留來源、hash、撤回原因與歷史，不能重用同一版號偷換檔案。
- 正常使用完全本地、無自動更新或上傳。安全報告由使用者手動匯出；僅增加必要的發佈／相容識別白名單，不擴大蒐集原稿、字型、原始客戶內容或私人檔案路徑。

問題狀態分清楚：**收到 → 已重現／待補條件 → 已修正並驗證 → 已發布待本機確認 → 使用者本機確認**。若軟體不能啟動，使用版本檔／發佈清單及可安全取得的啟動報告接續，不要求一定開啟GUI才可回報。
