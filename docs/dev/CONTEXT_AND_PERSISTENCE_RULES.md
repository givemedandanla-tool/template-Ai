# 核心規則：零例行對話、持久化

使用者於2026-10-15（Asia/Taipei）明確指定以下規則，適用所有後續開發與新對話。

1. **按需要讀取檔案。** 先用`rg --files`搜尋路徑、`rg -n`搜尋關鍵字，再讀相關段落。一般工具回傳限制在1600 tokens以內；獨立查詢可批次執行，但整次回傳亦保持精簡。大型日誌先查錯誤位置與尾部摘要，不一次展開整個倉庫、完整大型日誌或全部要求登錄。需要更多內容時分次讀取，明示尚未讀完，不能以截斷內容當完整證據。
2. **讓倉庫保存工作狀態。** 每個里程碑更新精簡`ACTIVE_DEVELOPMENT_HANDOFF.md`和`STATE.json`，記錄已完成事項、實際驗證、未決問題、下一步與精確提交／收據。詳細條款、設計決策、完整測試及歷史紀錄分檔保存；不讓接手摘要持續累加歷史。每可恢復階段及每10分鐘checkpoint、GitHub推送與讀回。
3. **新對話只帶交接資料。** 以倉庫、提交版本、精簡交接與目前工作包接續，不複製整串聊天。先執行`python tools/resume_status.py`；依需要按要求ID讀契約／測試／原碼。舊對話不可取得時如實說明，以GitHub可核對狀態恢復，不宣稱已爬取或還原完整聊天。
4. **大型資料使用適合的工具處理。** 圖片、PDF、模型和設計檔留在檔案／本機工具中，只取得需要的頁面、區域、結構、統計及hash。不得把模型、base64、整份設計檔或大量OCR全文灌入聊天。原檔、衍生資料、人工核准和輸出驗證分開，工具摘要不能冒充完整保真證明。

零例行對話表示自主執行已授權工作，不反覆問是否繼續或保存。較高優先指令要求的必要狀態訊息仍需提供；真正缺少必要外部條件只阻塞相依工作。沒有執行中的任務時，不宣稱有全天候背景開發服務。

GitHub是開發持久上下文；本機快照未推送／讀回前只算PREPARED。保留未提交、ignored與local-only資料，不reset或強制覆蓋。真實個資／私人原稿／密鑰不上傳；新證明媒體沿用既定metadata-first及精確hash政策，原碼、測試、文字證據與接手文件保存。
