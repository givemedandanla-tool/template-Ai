# 局部修改，怎麼決定要檢查多少？

不是每次都重跑整套，也不能只測剛改的檔案。先回答三件事：**改了什麼承諾？誰會用到？用哪些測試能抓到做錯的情況？**

| 修改 | 先查哪些地方 | 什麼時候擴大 |
| --- | --- | --- |
| 按鈕文字或提示 | 該視窗、對應操作與錯誤說明 | 也改到共用元件或操作接線 |
| Inkscape選擇 | 所有呼叫者、快取、來源分析、安全報告、真EXE | 換版本／元件、打包或Windows環境改動 |
| 資料欄位或家族規則 | 舊入口、人物／公司歸屬、多筆、Logo、預覽／確認／輸出 | 影響舊資料或已確認稿 |
| CI路徑、暫存目錄 | 受影響平台的環境與實際建置 | 關聯不清楚、跨平台或套件版本變動 |

檢查分三層：

1. **改動當下**：跑直接相關的正例與反例、曾失敗的案例、相關靜態檢查。
2. **功能穩定時**：實際走過受影響的操作鏈，例如匯入→分析→學習→輸入／預覽→確認與輸出。
3. **準備發佈時**：保留既有完整來源、GUI、Windows、真正EXE及下載後校驗門檻。

找不到關聯不代表沒有影響。未知時擴大；共用規則、資料版本、外部工具與打包設定不能漏掉。不得為省時間跳過人物歸屬、穩定ID、舊稿保護、確定性、無解與輸出阻擋。

若只是測試環境空間不足，先確認程式與測試bytes不變、恢復環境，再復驗受阻的完整模組；保留原失敗，逐案核對新記錄。不能把原FAIL改成PASS，也不能把這種彙整稱為單次全新完整執行。

每次保存基底／提交、影響理由、選中的測試、未涵蓋或未知部分、實際命令與結果、下一步及checkpoint。報告先附白話綜述，專業細節另放附錄；私人作品留本地。

目前由Codex依上述規則選測，配合既有免費工具與回歸流程。**全自動選測器尚未實作。**數學方法、Microsoft TIA、coverage.py、testmon及Cosmic Ray的適用與限制，見[完整方案](CHANGE_IMPACT_DEBUGGING.md)與固定來源研究。
