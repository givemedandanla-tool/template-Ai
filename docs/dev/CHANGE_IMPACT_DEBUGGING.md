# 變更影響除錯：以可查證的範圍取代每次全庫掃描

2026-10-22；本輪採用的開發流程。此文件是選測規則與實作路線，**尚未建成全自動測試選擇器**。現有 unittest、Qt 模組程序隔離、根因除錯技能及發佈全面 Gate 繼續使用；不購買平台、不上傳專案、不改測試框架。

## 要解決的問題

局部修改先回答「什麼行為可能改變」，再決定測試。只測修改檔案會漏掉呼叫者、設定、打包及快取；每次全跑則成本過高。檢查結果只能支持已驗範圍，不能證明軟體完全無錯。

一張變更單保留：比較基底與 HEAD、diff 雜湊、修改的符號／契約、受影響入口、風險、選中測試及理由、未選中理由與不確定事項、實際命令／版本／退出狀態、剩餘驗收及 checkpoint。相同基底與規則才能比較前後結果。工作目錄新增、刪除、改名與未提交檔也必須列入。

## 三層執行

1. 每次修改：直接行為的正反測試、曾失敗／新測試、相關 Ruff／型別診斷。優先數秒到數分鐘內取得根因線索，不反覆跑整個 GUI。超時或無法重現保留 UNKNOWN。
2. 一個功能穩定：沿影響圖跑受影響的完整操作鏈；例如工具選擇→向量匯入→來源恢復／幾何→學習及既有輸入預覽→安全報告／快取。各 Qt 模組獨立程序，不替換關鍵視窗、不減弱原斷言。
3. 發佈里程碑：現有完整來源、原版 GUI、治理、Windows 適用案例、真正凍結 EXE、下載後逐檔校驗全部保留。每天局部修改不重做這層；穩定候選正式做一次，有新產品程式變更時重新資格化。工具／版本／資料契約／全域啟動等大影響變更提早升級此層。

測試總時間須以實測為準，不預先承諾百分比省時。發布必要 Gate 不列為可省略候選。

## 如何推導影響範圍

令圖 G 的節點為函式／模組、資料契約、設定、資產／外部工具、流程及測試；邊 a→b 表示 a 依賴 b。對變更集合 Δ，從修改前與修改後圖的聯集作反向可達搜尋。刪除／改名不能只看新圖；一般 BFS／DFS 的成本是 O(|V|+|E|)。

候選集合 = 靜態反向依賴 ∪ 動態覆蓋關聯 ∪ 人工明示的資料／設定／跨程序契約 ∪ 既有失敗 ∪ 新／修改測試 ∪ 固定安全底線。這是保守聯集，不以「動態覆蓋沒看到」刪掉已知靜態依賴，也不以固定兩層深度截斷。模組層圖過寬時逐步細化到符號與契約，不能直接忽略共用入口。

Python 的動態匯入、反射、Qt signal／slot、子程序及 PyInstaller hiddenimports 不一定能由 AST 找全，必須有明示邊。例如 release-info pin→runtime resolver；TEMPLATE_AI_INKSCAPE／PATH→僅來源模式；runtime identity→快取鍵／來源有效性／品質 manifest／安全報告；release workflow→實際凍結包。相依資料缺少、過期、工具升級、未知檔案類型時擴大到流程或完整層，不把空集合當通過。

動態覆蓋索引綁定來源、測試 catalog、工具、Python／Qt 與環境版本。coverage.py 可用 context 記錄 unittest 的逐測試覆蓋；不要求改用 pytest。原 Qt worker 每個程序使用獨立 coverage 檔，結束後合併；先在少量模組量測時間與資料量，再決定是否常態收集。覆蓋只證明執行過，不能證明有正確斷言；資料過期不能作排除依據。

## 數學方法用在排序，不能洗掉未知風險

把重要契約／故障視為集合 R，測試 i 的實測成本 cᵢ、可查證覆蓋 Cᵢ。可求解 min Σcᵢxᵢ，限制每個必要風險被覆蓋、必要測試 xᵢ=1。這是帶權集合覆蓋，可用「新覆蓋風險權重／成本」貪婪排序快速取得回饋；沒有證據的覆蓋不得填入 Cᵢ。高風險的資料歸屬、舊稿版本、確定性及輸出阻擋不能因成本高而取消。先失敗的測試優先執行，修正後回到相關完整流程。

## 這次隨包修改的實際範圍

| 修改／契約 | 必查行為 | 本輪入口 |
| --- | --- | --- |
| frozen resolver | 系統／env／PATH 誘餌不能蓋過包內；缺少與損壞不得備援 | test_bundled_inkscape；真正 EXE engine probe |
| renderer identity | 換引擎產生新快取；舊快取不覆寫；影像輸入獨立 | test_inkscape_cache_identity、test_source_cache |
| 外部工具呼叫者 | SVG／PDF相容 AI 真轉換、幾何查詢、來源恢復 | 原 source／recovery／learning 模組；真 EXE callee 記錄 |
| 安全報告 | 引擎損壞仍可匯出；舊報告可讀；不帶私人路徑；無 Qt／site-packages CLI | 原 test_offline_support；新增 report schema；真正 EXE report CLI |
| 包裝與授權 | 僅精確 vendor 清單允許；不隱藏私人 DB／字型；來源附件 hash | test_bundled_release_guard；manifest／全部下載校驗 |
| 全域相容性 | 原輸入、人物歸屬、版本、學習、排版、更正、確認、重啟及輸出 | 原來源全面 Gate、Windows 原案例與 EXE 原21檢查 |

「只改工具路徑」的第一階段可先不重跑與工具無依賴的欄位分類演算法；這表示安排到候選發佈層，**不是證明其不受影響**。發現模型 manifest、匯入 DTO、共享設定或全域啟動也改動，立即擴大。不能只用檔名比對排除。

真實抓到的案例：路由與快取測試先通過，但安全報告新增工具版本資訊，間接載入 NumPy，破壞原「無 site-packages 也能匯報」測試。紅燈保存在 releases/v0.2.0-beta.2/support-regression-red-001；版本探查移到標準庫模組後，原21報告測試通過。這就是資料消費者／最小啟動契約需要納入影響圖的原因，不是靠多跑同一個路由測試解決。

run_routing_faults.py 在合成測試內注入「env優先」與「缺包改用系統」兩種故障，要求選定測試真的失敗；原版必須通過。它證明斷言對這兩種錯誤有力度，不等於已找出所有缺陷或取代真 EXE 驗收。未來只對高風險修改做有限變異測試，不對全庫無上限反覆變異。

## 導入與維護

目前交付：本流程、來源研究、這次選測與實際紅／綠燈、故障注入、原生包內呼叫驗證。下一步可在既有 quality.py 旁加「只產生選測建議」的 AST／契約圖與 coverage context 索引，先人工覆核幾個真實修正；比較完整回歸的漏選與時間後，才允許自動執行建議。每逢新故障，增加能重現的契約邊或測試，再追根因；不刷新基準藏問題。

來源與適用限制見 CHANGE_IMPACT_DEBUGGING_RESEARCH.json。Microsoft TIA 的商用流程可借鏡，但其 VSTest/.NET 實作不能直接裝進本專案；pytest-testmon 是 pytest 外掛，只參照依賴追蹤；Cosmic Ray 是開源 Python 變異測試，現階段僅採有限故障注入原則。未啟用付費服務、外部模型或新增代理。

## 本輪環境復驗與資料接線的補充實例

新增快取欄位的內層型別也要列契約：renderer_identity為null／數字／陣列／字串，現在會安全重建，舊cache完整性檢查仍保留。定向授權檔檢查另外抓到報告輸出目錄與蒐集目錄不一致，已改共用OUT；這屬於資料生產者／消費者的接線，不應為它重建整個EXE。

完整來源嘗試003遇暫存空間峰值不足；所有46案例錯誤都是ENOSPC，另有兩個class-setup錯誤鏈與一個模組deadline。沒有將原結果改成PASS。先可逆壓縮非正式輔助metadata、核對SHA，再只跑14個受阻完整模組（139案），來源bytes、斷言及180s上限不變。既有正式adopter從實際健康模組逐案採錄並驗證完整1986名錄，原失敗／missing／runtime全部保留。這種證據明標「相同來源多次健康模組彙整」，不能稱單次新全跑，也不以重試吞掉未知產品錯誤。

未來圖運算可重用現有networkx的反向可達性；有需要才使用現有SciPy的最佳化能力，先以人工核對的建議模式驗證。測試成本與關聯資料來自實測，不能憑空填滿覆蓋集合。
