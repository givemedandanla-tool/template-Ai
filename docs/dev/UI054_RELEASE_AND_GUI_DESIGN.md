# UI054 原11：接線與版本放行設計（尚未整合／驗收）

本文件補充 UI054_EXECUTION_PLAN，不能當作功能完成證據。原11全文與來源SHA仍以該計畫／固定28契約為準。正式005回歸期間只保存設計與未執行草稿，不改受測程式。

## 重用與資料邊界

- 沿用 TrainingStore 的同一 SQLite、版本／事件／CAS，及現有 Source、FACTS、RULE、SEMANTIC_MODEL、COVERAGE、QUALITY_*。修復只新增必要憑證；不複製人工答案、另建資料池或品質引擎。
- 修復頁重用 QualityPanel.request 的受控命令傳輸；擴充現有 quality_command 的 REPAIR_* 分派，使用既有 Library 連線。不要再開第三個命令協定或排程器。
- 語意候選訓練是 AUTO_JOB 的明確 operation，重用原 claim／finish／共享 lease／子程序／資源背壓／備份恢復。每一項必有真正來源與工作範圍；確認來源完成和模型完成分開呈現。
- 人工更正走現有來源事實、標記、雜訊、客戶修訂入口。不得為了修復一次錯誤直接回寫客戶、原稿、正式模板或全域規則。

## 嚴格的證據順序

1. **原案例重現**：同一合法來源與目前有效人工標註，執行實際舊失敗版／實際候選。原來源變更或真值有爭議先阻擋；不能拿手填的修復成功取代來源推論。
2. **關鍵反向對照**：明列未受影響的人物／聯絡歸屬、多作品、完整 Logo、物理尺寸及客戶版次。缺相關真值或必要對照不得稱沒有退步。
3. **新獨立驗收**：沿用 UI053 正規固定 A/B、品質政策及群組不確定性。已曝露的保留集永久保留失效紀錄，不可改名、複製或重新訓練後當新保留集。
4. **歷史影響處置**：需要人審的重大歷史項目逐件有新憑證；修好單一作品不等於解除模型／規則組件的系統性隔離。
5. **具名人工採用**：只有前四項與規則獨立核准皆符合，才提供明確採用。模型／規則／解析器／OCR、資料集／Gold、來源與各 Gate 憑證一併保存。

必須擴充原品質協定，讓已曝露 HOLDOUT 可在**明確的修復描述性 replay** 下重現錯誤；其獨立性與 quality_pass 永遠為假。不把它改成 TRAIN／VALIDATION，不修改原測試集的歷史標記，也不建立第二套評分公式。該擴充尚未實作，不能先用一般 HOLDOUT 協定繞過限制。

## 規則候選與真實啟用

- 原規則草稿與獨立核對後的候選版本分開；候選保持非 ACTIVE。來源草稿標記隔離，避免從一般審核入口提前發布。原有批准風險檢查要抽成共同函式供兩路重用。
- 凍結引擎可明選已獨立核准的隔離候選規則；支持／反例與 TRAIN 曝露歷史持續生效。品質批准和正式發布分開。
- 正式版本採不可變部署事件＋CAS 的目前版本參照；不能只改畫面標籤。後續新來源的 AutomaticTraining 實際路由到該凍結 pipeline，既有確認資料與模板不被覆寫。
- 預檢／工作範圍保留 exact 部署／模型／規則版本；排隊期間版本變動不可悄悄換版。恢復原工作仍要核對原版本自身的有效憑證與隔離狀態。
- 前景查詢用有界資料與既有背景核對；正式採用／輸出邊界仍做來源實質驗證。不能為每個欄位無條件重掃全部歷史測試原稿。

## 實作前必測

- 真正訓練的新模型／實際來源推論修好原錯誤；失效 holdout 真值不進訓練。
- 原問題修好但新重大錯誤／關鍵類別退步、對照不足、來源變更、未結歷史重審皆阻擋。
- 實際部署後的新來源確實使用所選凍結版本；原模板／客戶／原稿不變。
- 舊版也嚴重錯誤時兩版均不能當安全回退；相同程式／參數／規則換 ID 不能洗白。
- 規則候選未啟用前不參與正常 ACTIVE 規則；明確採用、撤回、回退均有原子憑證。
- 取消／背壓／程序中止／磁碟或晚期事件失敗不留下半成品信任；復原後明確續跑。
- 真 Qt 七頁、所有入口、50分頁、延遲資料、未保存人工更正保護；不得用純字串狀態取代 GUI 和實際結果。
