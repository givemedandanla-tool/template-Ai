# 同模板交換、聯動參數與預設優選學習計畫

2026-10-19｜設計／訓練要求，尚未實作或訓練。依[使用者決策](../decisions/2026-10-19-CORE-ADAPTATION-SWAPS-AND-DEFAULTS.md)與[有效契約](AI_CROSS_WORK_LEARNING_CONTRACT.json)。

## 1. 要得到的能力

客戶輸入 → 取得完整稿 → 按需要交換相對位置 → 核心在同模板規則內適配 → 必要時比較其他相容模板 → 確認並重用精確定稿。

優先讓同一模板／家族承接合法排列變體。後台遇到多個合法結果時，一律依預設優選與穩定決勝取得可重現結果；客戶已決定的關係優先。

## 2. 共同表示與聯動參數

重用現有DesignObservation、TrainingStore、人物／公司／欄位ID、文字量測、關係圖與版本機制。

| 條件／參數組 | 必須保留的資訊 |
|---|---|
| 上下文 | 家族／風格、實體尺寸、語意角色、人物公司關係、資料組合、實際字型、資產與政策版本 |
| 結構 | 欄列／群組、容器範圍、錨點、基線、切齊、相對關係、交換／重排及鄰接依賴 |
| 聯動向量 | 欄位寬高、來源／配置pt、水平縮放、實際文字占位、tracking、分散單位／邊界、padding／gap與角色層級 |
| 依據 | 來源與變換、獨立lineage支持、合格標記、缺失遮罩、反例、不確定性與適用條件 |

學條件／聯合／可能多模態的風格區域。各參數分別落在min/max內，不代表其組合合法；少量合格風格亦須保留。量測仍使用實際字型與文字，未知來源字型／pt保持UNKNOWN。

客戶不操作字級、字寬、欄位尺寸、切齊或分散細參數。印刷精度與可識別差異需來源／製程證據，不能自行指定任意毫米或pt步進。

## 3. 三項既有訓練設計待辦的擴充

- TRAIN-DESIGN-01／DataRequirementProfile：資料在各家族／角色的實測空間需求、合法呈現模式及文字配置聯動；原始姓名、客戶編號不作風格辨識捷徑。
- TRAIN-DESIGN-02／FieldCapabilityProfile：欄位的條件承接能力、雙向交換候選、聯合容量、相對關係，以及保持家族風格的適配範圍。
- TRAIN-DESIGN-03／條件相容與替代：保存兩個目的地同時成立的交換證據、資料／標籤／圖示映射、客戶意圖及預設欄位指派。跨類替代仍可能有方向，不能假定對稱或可傳遞。

三項是共用表示的邏輯視角，不預設三個獨立神經網路。來源支持、政策允許與當次整體可行性分開輸出。

## 4. 同模板交換的訓練目標

1. 從同家族的獨立作品變體與確認過的欄位關係，取得角色／容器／排列對應；不能只按框位相似度推定可交換。
2. 產出條件交換關係與影響範圍：兩個目的地、主人、標籤／圖示、實際占位、可聯動參數與必須保留的相對關係。
3. 以實際量測與整體求解驗證交換後的兩邊及周圍布局。語意相容與容量可行須同時成立。
4. 同模板可合法適配則保留該家族／模板身份，以排列／綁定變體表示，不為每個排列建立一張新學成模板。
5. 超出家族支持的聯合區域或已證實不適用時，再比較其他相容模板；未知／逾時另列，不冒充已證實無解。

尺寸相似度、容許失真及何時換模板的數值界線用VALIDATION校準；不先指定「差10%可交換」等無依據限制。

## 5. 預設優選模型與穩定決策

| 決策層 | 要產出的預設 |
|---|---|
| 家族／模板 | 多個合格候選的適用性與優先順序；已有有效定稿時先沿用該次綁定 |
| 欄位指派／排列 | 同一角色可綁多欄時的預設位置、相對順序及條件；客戶明確交換覆蓋該部分預設 |
| 結構變體 | 可選／重複／欄列等合法分支的預設選擇與穩定決勝 |
| 聯動參數 | 聯合合法區域內的代表配置與次序，避免每次任意抽取不同pt／字寬／尺寸 |
| 同分／等價候選 | 版本化、可重現的最後決勝規則；不依隨機、資料庫返回順序或並行完成順序 |

可用合格TRAIN作品中的條件頻率與確認過的預設配置建立基準，保存支持與反例。常見不等於美感最佳；沒有真實比較資料時，不假造偏好標籤或機率。統計仍無法決勝時，使用可追溯的版本化核心預設，且標明其依據。

對同一條件建立一致的合法候選比較順序，所有合法多解決策都有後續決勝。未知／未驗證候選不能因分數較高而當作合法。有限候選是在後台處理；客戶仍直接取得完整稿。

不同家族可學到不同的市話／手機預設位置；此例不設定全域市話必左。候選評分、決勝策略、字型量測、文法、資產、搜尋範圍及有效版本需可追溯。

## 6. 重複訂單與版本

保存有效輸入的保守規範化表示：資料、穩定身份／歸屬、尺寸、已決定相對關係及必要生產條件。不得任意刪空白、改語意或以相同字串合併不同資料。

首次產稿依穩定規則選擇；確認後綁定實際可印結果、規則／模型／資產與依賴版本。相同有效輸入再次下單，讀取仍有效的已確認結果，不因模型升級重新隨機排一張。新內容或明確改版需求建立新版本，保留仍適用的客戶意圖。

重印應能取得精確保存產物；只保存JSON後用新版引擎重算不證明相同印紋。首次求解的生產內容一致性與重取封存產物的bytes/hash一致性分開驗證；不把PDF日期欄等非印紋差異當成學到不同風格。

固定排序／代表解是支援穩定結果的方法，不聲稱所有連續幾何的數學合法解真的只有有限個。不以微小隨機參數差異製造無意義版次。自動採用背景改善候選的時機仍OPEN，並未在此授權。

## 7. 演算法與重用依據

- 數學：條件／聯合分布、穩健統計及條件回歸用於參數聯動；角色相容圖／指派關係表示合法交換；分層比較與穩定決勝處理多合法候選。具體模型／閾值仍須驗證。
- 重用Qt文字塑形／量測、既有圖表示、Kiwi/Cassowary與交易／版本儲存。求解器在選定結構下求位置，不自行發明所有離散結構或原稿字型真值。
- 家族候選、條件估計及排序沿用主方案；資料不足時先做可比較基準，不直接假定需要新大型模型。
- 商用公開思路參照Figma元件／Auto Layout與屬性綁定的結構、配置、實例分工，不宣稱重用其未公開AI演算法。
- 已核對的來源、版本、hash及授權見[工程參考](AI_CROSS_WORK_ENGINEERING_REFERENCES.json)與[綜合參考](AI_TRAINING_COMPREHENSIVE_REFERENCES.json)，尤其figma_types、qt_textlayout、kiwi_readme。這輪未安裝新依賴或使用付費服務。

## 8. 待執行驗證與衡量

| 案例 | 必須驗證 |
|---|---|
| 同家族兩個聯絡欄都可放市話／手機 | 未指定時每次採同一預設；重新啟動及打亂候選列舉順序也一致 |
| 客戶要求左右互換 | 保留同家族合法變體、資料主人與必要標籤；重開不被原始預設覆蓋 |
| 欄框接近但長度／字型不同 | 兩個目的地與整體共同驗證，不只測框大小 |
| 可合法聯動調整的不同大小欄位 | 欄位尺寸／pt／字寬組合位於合格風格聯合區域，且保留客戶關係 |
| 單項都在範圍內、組合卻不合格 | 拒絕錯誤聯合組合；與獨立min/max基準比較 |
| 語意、主人或固定標籤不相容 | 不因幾何接近就允許錯誤替換或變更歸屬 |
| 當前家族確實不適用 | 才比較其他合格模板，仍保留客戶意圖；未知與失敗分母完整 |
| 兩個合法候選同分 | 依明確預設／決勝選同一結果，不隨機變動 |
| 不同家族預設相反 | 按家族條件保留差異，不硬併成全域預設 |
| 同輸入重複訂單及模型更新 | 仍沿用有效已確認版與精確產物；不得默默製作新印紋 |
| 內容／客戶關係改變 | 新版可重算，仍適用的舊決定保留，舊確認不得冒用 |
| 來源字型未知或缺少合格證據 | 保持UNKNOWN及原因，不以預設值湊出合法交換／風格支持 |

依lineage隔離TRAIN／VALIDATION／封存TEST；報告交換合法率、同家族承接率、錯誤接受／拒絕、關係保留、預設一致性、定稿重用率、換模板原因與失敗／未知分母。合成技術可行案例不作獨立美感真值，真實偏好需獨立比較資料。
