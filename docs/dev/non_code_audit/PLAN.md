狀態：**DESIGN_COMPLETE_NOT_EXECUTED**。本輪完成方案與公開資料研究，沒有執行本方案32項檢查、修改產品、安裝工具或重跑產品測試。

適用來源：`24202acab96c84f81aede27eb947d3975be1851f`及其僅文件後續提交。既有1921PASS、27項GUI作業、19項桌面檢查繼續保留各自範圍，不算本方案已驗收。本方案的8個面向／32項檢查是排查清單，不新增或重編原8個AI工作包、50條驗收、75父題及172需求。

## 1. 要找出的錯誤

目標是找出「程式可以照寫好的邏輯執行，但這套邏輯、輸入或判斷本身有問題」：需求理解錯誤、規則互相矛盾、資料配錯對象、學習結論超出證據、流程默默換版本、看似正確的稿件實際漏字／錯資料，以及報告說的完成範圍大於證據。

這是依錯誤根源分類，不是宣稱這些錯誤永遠不需要改程式。正式執行若發現產品問題，先保存最小反例與影響，再按根因處理；本輪只有設計授權，不先做產品修正。

核心判準是「做對使用者要求的事情」，不能只用「沒有例外、畫面正常、測試有跑」代替。

### 不改動的產品原則

保留人物／公司歸屬、共享關係、穩定ID、Logo綁定與完整資料；同模板合法交換優先。字級、字寬、欄位大小、切齊與分散由核心的已核准規則聯動，客戶表達相對位置意圖；不重新加入已撤回的字級／字寬／單雙排控制。

拖動時保護不受影響的相對關係，不能誤解成所有座標、字級與欄位尺寸一律凍結。既有固定模板與已確認稿保留原版本；web／手機／EXE維持延後。私人作品、字型、DB與模型留本地，沒有私人資料不妨礙先做合成機制驗證。

## 4. 用邏輯學避免「測試自己證明自己」

### 4.1 先建立規則台帳與適用範圍

每條規則記錄規則ID、使用者／核准決策來源、適用版本與對象、必要條件、結論、例外及被哪條後續決策取代。先區分歷史敘述、新家族規則、舊模板與已確認稿，再判斷衝突；不能看到兩段文字不同就自動刪除其中一段。

用決策表顯式檢查：同輸入是否命中互斥結論、是否完全無規則可用、是否有多個合法答案而沒有優先順序、優先順序是否成環。分開硬性規則、偏好及來源不明的經驗假設。已撤回規則不得因歷史文件仍存在而重新啟用。

### 4.2 區分必要條件與充分條件

「字放得下」只是部分條件，不能推出語意、歸屬、圖示、相對位置及輸出都合法。「樣本曾出現」不能推出任意新輸入也安全。「通過1921測試」不能推出所有需求與資料組合都已驗證。

合法排版必須同時滿足所有適用硬性規則。只有缺少可行解證據時，不把推測當已解決；有界子模型UNSAT只表示該模型／界限內無解，不自動宣布所有模板永遠無解。

### 4.3 條件等效不能無條件傳遞

以`可替代(來源角色,目的欄位,資料,家族,版本,環境)`表達相容。A能在某條件替代B、B能在另一條件替代C，不能直接推出A可替代C。避免只用尺寸接近或union-find傳遞閉包，將不合法的欄位永久合成一群。

同種類資料的共用規則與同欄位的跨種類容納能力分開量測，再以實際資料和聯合約束決定是否合法。

### 4.4 可行性與優選分開

先找出合法集合，再依已核准、版本化的優選選出預設稿。優選可採明確的字典序：已確認／保護意圖、合法同模板適配、適配成本與風格偏好、最後穩定ID破同分；具體順序先對照現有政策，不在排查中偷偷更改產品排序。

若排序後仍有複數等價結果，需有明確、穩定的破同分規則。穩定排序只保障重現，不代表審美更好；不能以固定hash取代設計品質判斷。

確定性的前提包含正規化輸入、人物／欄位ID、操作意圖、模型／政策／字型檔／資產／排版器與輸出設定版本。相同輸入但換模型不是同一條件。重訂優先重用已確認artifact的原始bytes；新生成的稿件另檢查內容／幾何與檔案metadata，不能忽略時間戳等差異卻聲稱byte完全一致。

### 4.5 反例、變形測試與獨立答案

每項至少安排正例、反例及適用的未知／邊界。用小型手算／窮舉、人工撰寫的期望表、核准規則與既有獨立數學oracle比對；不能直接呼叫同一個排版函式產生「標準答案」再跟自己比。

變形只在前提成立時使用：不承載使用者順序意圖的序列化重排不改結果；更正某人的電話不改owner；真正復原應恢復受該操作管理的內容／關係；相同確認稿重訂取得同份artifact。不能要求所有資料重排、改尺寸或增加欄位後整張稿永遠不變。

查到失敗時縮小到最少人物、欄位、規則與操作步驟。邏輯求解只處理可明確編碼的有限角色／量化幾何子集，實際文字成形與完整preflight仍由現有引擎驗證。若資源上限內無法判定，結果為UNKNOWN；不反覆無上限窮舉。

初始生成預算：每項最多200組候選，固定seed `0/7/42`在該總額內分配，或累計120秒先到即止；求解器每個子模型最多10秒，亦計入該項總時間。這是首輪調查上限，不能因未找到反例就當完整證明；超時／未覆蓋部分記UNKNOWN，只有具體剩餘風險才另增有理由的調查。既有正式unittest／Qt擷取的程序隔離、斷言與期限不因本預算改動。

## 5. 學習品質怎麼查，不能怎麼宣稱

先用可控制因素的本機合成作品：多人物／共享資料、同畫板多尺寸、近重複改版、噪音標記、未知字型、合法與非法交換、聯合容量中的洞及稀有合格風格。人工制定golden標籤與預期家族／關係；不得直接把目前模型輸出當真值。

依design lineage先群組再切分，必要時另報客戶外推的獨立留出結果；測試資料不能回流選參數。不能把客戶編號／檔名當風格特徵，也不能為追求低模板數強併不同合格風格。以訓練與驗證資料定候選閾值，凍結後才評估留出集。

正式有授權資料時，分開報語意辨識各類precision／recall、家族錯併／錯拆、合法交換誤接受／誤拒絕、容量錯放行、排名／偏好一致性、UNKNOWN與支持量；按家族／語言／字型等切片，不只報一個平均數。統計區間以獨立lineage為單位，資料太少時明示不確定；不先虛構準確率目標。

合成作品只能驗證機制是否可學、規則是否可表示、反例能否攔截。真實訓練品質、原生.ai完整還原、Windows／指定硬體與實體印刷仍是原先延後資格，不要求使用者把私人作品交到雲端。

## 6. 執行順序與停止條件

1. **先校準「什麼算正確」。** 凍結版本與需求／決策優先級，建立規則台帳；對初步文件訊號確認版本／範圍。正式治理證據過期問題優先列為證據缺口，不當成已通過，也不誤報為產品崩潰。
2. **先查高影響錯誤。** 先做人物／共享歸屬、舊定稿保護、資料不遺失、錯稿被允許輸出與私人資料外洩的反例，再做一般風格與操作一致性。
3. **查資料→學習→約束。** 用獨立期望表與控制樣本，檢查洩漏、偽學習、容量、條件替代、優選與確定性。
4. **查整段流程與產物。** 沿用真實桌面入口和相同核心完成更正、拖動、取消、恢復、確認與輸出，對照中間資料及artifact；不以替換視窗的測試取代接線檢查。
5. **查報告是否可信。** 在隔離樣本故意放入錯owner、衝突規則、未知來源、過期確認與錯hash，證明檢查確實會拒絕；不得改正式產品或歷史證據來製造演示。
6. **收斂與保存。** 每項有結果、適用範圍、證據與下一步。若實作修正另獲授權，只做必要根因修正及相關回歸；無新程式／失敗／具體風險時不重跑全套。

嚴重度先看後果：P0資料遺失／外洩／錯人資料或定稿破壞；P1可完成但產生錯稿、關鍵規則失效或錯誤放行；P2一般一致性／可用性／維護風險。是否屬於原碼缺陷不影響嚴重度。缺少真實資料時不猜發生率，不用主觀相乘分數把P0排到最後。

## 7. 結果、證據與驗收

檢查結果只用PASS／FAIL／UNKNOWN／NOT_APPLICABLE；執行狀態另記NOT_RUN／COMPLETED／BLOCKED_EXTERNAL／DEFERRED。UNKNOWN、未執行與延後不得計入PASS。NOT_APPLICABLE必須有適用性理由。

每項證據包含：核准依據與scope、來源／資料／模型／政策／字型版本、獨立答案的來源、正例與反例、實際結果、限制、最小重現及安全證據路徑。完整issue另含白話綜述、專業分析、受影響對象、風險與可行下一步；私人內容與可識別截圖不自動進Git或報告。

正式排查的收斂條件：

- 32項全部有可核對的處置；需要外部條件的子範圍明確保留，不能硬湊32PASS。
- 現行全部驗收條款有面向／獨立期望／原延後原因的映射，未覆蓋與尚未定義的規則明列，不靠主題數宣稱全面性。
- 支援且已驗範圍沒有未處理的已重現P0／P1；每項關鍵檢查有反例能被攔截。
- 規則衝突、文件／證據狀態差異有scope與來源裁決，不能靠刪除舊記錄或放寬檢查消失。
- 資料、畫面、確認與輸出依同一不可變版本／artifact核對；定稿與重訂不被新模型默默改寫。
- 原碼測試、非代碼排查、真實學習品質與外部印刷／硬體資格分開報告；不宣稱零錯誤保證。
- 結果、精簡交接、checkpoint與GitHub讀回證明保存，私人資料留本地。

本輪設計交付的驗收僅是：來源可追溯、32項清單與執行方式完整、沿用既有能力、未改產品／原資格、文件一致並已保存。它不代表以上排查已執行通過。

執行交付預定為：`rule-ledger.json`（規則與優先級）、`requirement-audit-map.json`（完整條款映射）、`case-results.jsonl`（正反例與結果）、`issues.jsonl`（根因／風險／安全重現）、`FINAL_REPORT.md`與精簡交接；本輪尚未產生這些執行結果。非代碼排查也不會自動消除既有Pyright型別診斷，兩者分開追蹤。
