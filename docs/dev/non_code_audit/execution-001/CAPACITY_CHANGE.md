# 容量建議語意修正

兩個獨立反例確認：大量成功樣本會讓同區間的已知不合格／失敗點被當正向支持；另一個家族／尺寸下的最大欄位數也可能被帶入目前條件的回覆。兩者影響容量提示，沒有證明可繞過實際排版或正式輸出Gate。

修正後只有排版通過且人工風格合格的紀錄形成正向支持與邊界。已知負例保留；同需求點有矛盾時回覆UNKNOWN，不以多數票說成已核實。整體最大欄位數保留作跨條件統計，但查詢只回覆匹配條件的已驗欄位數，不宣稱全域硬上限。

校準格式升為`conditional-capacity-calibration-2`。舊v1紀錄保留不改寫，明確重校準前不再當可用建議；沒有重寫模型、原模板或定稿。真實SQLite／已綁來源模型的獨立場景已驗證：舊校準被拒絕但原紀錄保留，正常預覽仍可確認及輸出。正式印刷、原生.ai與真實學習品質資格沒有提升。

反例與修後證據：capacity-before.log、context-count-before.log、context-count-after.log、targeted-oracles-003、semantic-probes-002。最初的缺產品相依Python、報告測試誤用命令回傳值、legacy probe未提交fixture交易，皆保留並標為無效環境／fixture，沒有改產品去迎合它們。
