# 驗證計畫與開發關卡 v0.1

狀態：**PLANNED / NOT VERIFIED**。下列皆是未來驗收標準，尚無 PASS。

## Gate 0：來源與既有資產盤點
- 盤點現有名片自動排版程式及授權；標明可直接重用、需改造、不能重用。
- 每個第三方依賴留來源 URL、精確版本/commit、授權、Windows 支援、維護風險與替代方案。
- 以匿名化測試作品建立多作品、註解、異形、不同尺寸、缺字型、效果外框的真實樣本集。

## Gate 1：Illustrator 解析
- 真實 .ai 文件的多設計切分、原生文字/效果、物件座標、字型狀態、人物/公司/Logo 歸屬有可人工核對的測試報告。
- 無法判定時回報 UNKNOWN/REVIEW_REQUIRED，不臆造欄位或尺寸。

- **UI-031 Illustrator 文字效果／缺字型安全診斷專項驗收（尚未執行）**：
  1. 用合法或去識別 .ai 真實案例覆蓋**可編輯原生文字**、原生文字套用 Illustrator「效果 → 路徑 → 外框物件」、真正建立外框的轉曲文字、文字與向量混合、只有 PDF 外觀層而缺失原生文字資訊、OCR 誤判等；由 Illustrator 中能查驗的物件及效果作對照，測試不混淆**外觀效果**與**實際轉曲**。
  2. 驗證來源判讀須先檢查可取得的原生文字、字型與效果資訊，再輔以向量與原稿視覺，OCR 只用作補救；GUI 對可編輯性／來源類型區分**已確認、推定、未知**，不從圖片外觀虛構原始字型、原始字寬百分比、文字可編輯性或精確字級。
  3. 使用缺字型、別名字型、Windows 安裝字型和使用者合法匯入字型的測試集，確認介面能列出受影響人物／公司／欄位、原稿對照、候選字型與可核實的字形／實際字寬差異；替代字型**不得直接標示為原始字型或默默套用**，高風險及不確定項目需人工核准，字型系統安裝須得到明確授權。
  4. 替換字型或修正文字物件後，須維持 UI-013 **字級先行定案且不隨文字長度更改**，檢查實際字寬、核准的字寬壓縮及字距、文字完整性、對齊、最小可讀性、安全區、重疊、真實輸出格式及最新驗證狀態；不合格不能宣告正式輸出 PASS。
  5. 驗證 Logo 內文字被正確保留為 UI-020 完整複合 Logo 的構成部分，不能因一般字型替代而拆分、重新排字或改變商標原貌；Logo 外部真正獨立文字框才套用一般欄位文字處理。
  6. 對尚未取得的原生解析資訊、缺字型及可靠性低的 OCR 候選，驗證可交由既有例外／人工審核流程，記錄來源、修正前後差異及局部重驗證；來源無法支持正式輸出的情況應保留清楚問題與非正式診斷預覽，不得以推定資訊通過 Gate。
  7. 以上**僅為待執行驗證方案**；目前尚未運行 Illustrator 原生效果解析、字型匹配、字型匯入或實際輸出測試。

- **UI-038 多作品總覽／智慧辨識框／畫布直接標記修正驗收（尚未執行）**：
  1. 使用已取得授權／匿名化的真實 Illustrator .ai 測試：**單檔多畫板多作品、單畫板多作品、跨畫板圖形、同尺寸不同版型、不同尺寸混合、註解／草稿非名片物件**，驗證系統不能把一個檔案或畫板直接等同一個作品；各候選作品的縮圖、來源畫板、邊界、尺寸與可信度必須可與原稿逐張人工核對。
  2. 驗證作品總覽能搜尋／篩選／快速切換，每張作品顯示實際有證據的識別狀態、待修正問題、訓練／審核進度；未知人物容量或實體尺寸需標示推定／未知，不可虛構統計或假稱完成。
  3. 驗證在**作品原稿畫布直接顯示並操作兩層 AI 智慧框**：一層為整張作品邊界候選，一層為作品內的姓名／職稱／電話／Email／地址／獨立公司文字／整體複合 Logo 等資料與物件候選；可直接點選、高亮、框選補漏、修改邊界、修改語意與人物／公司歸屬，**不能只有不可編輯的視覺框或只能在右側清單修改**。
  4. 建立故意錯分作品邊界、漏標欄位、把姓名歸錯人物、把另一張名片物件混入、把圖文複合 Logo 的文字錯拆等案例，人工在作品畫布修正後應保持**作品與來源 .ai／畫板／原生物件識別**可追溯，人物／公司資料不得混用，完整 Logo 仍保留圖文與比例。
  5. 比較拖曳**標記候選框／作品切分框**、拖曳真正模板物件及 UI-037 視角平移：修正學習框位不能偷偷改動原 Illustrator 檔、原文字字級、Logo 形狀或草稿真實座標；原稿／AI 疊圖／右側屬性／左側語意樹同步定位正確物件，未知映射須顯示疑義。
  6. UI-004／UI-006／UI-007 程序需能處理**AI 提議 → 人工修改前後比較 → 明確確認／保留待審 → Undo／Redo → 受影響作品與依賴項局部重新分析**；一個作品標記核准不等於全文件、跨作品或永久學習規則核准。原始 .ai 與已發布模板不能被覆寫。
  7. 需驗證暫時標記、AI 候選、低可信度或語意歸屬不確定內容無法直接當作正式已確認訓練資料／模板發布品質 PASS；UI-013 固定字級、UI-020 完整複合 Logo、UI-023 卡片尺寸獨立 Logo 庫及印刷品質 Gate 不可被繞過。
  8. 以上均是**尚未執行的驗收案例**；並無實際智慧框、AI 作品切分、互動標記、訓練或程式開發成果。

- **UI-039 智慧框畫布直接標記、快捷修正與分級確認驗收（尚未執行）**：
  1. 使用合法授權／匿名化的單檔多作品 Illustrator .ai 樣本，驗證能於每個作品原稿畫布上**直接點選 AI 智慧資料候選框、框選新增漏標、拖動修正邊界、修改欄位類型及人物／公司歸屬、明確拒絕錯誤候選**；畫布快捷選單應在選取處就近提供欄位類型、人物／公司、來源對照與確認，不得只能藉由另一頁表單完成。
  2. 測試姓名、職稱、電話、Email、地址、IG／LINE 等實際欄位與完整複合 Logo 的標記，確認「公司 Logo 所有者是公司」且 Logo 包含圖形與文字；OCR 公司名若在 Logo 內不能誤拆成可重新排版的獨立公司字框，已核准不同卡片尺寸 Logo 庫不得交叉借用。
  3. 在畫布點選某框及由左側語意樹／原圖層／右側屬性面板反向點選同一框，必須相互定位正確物件並顯示**AI 候選／人工更正、來源 .ai、作品、畫板、實際可驗證幾何、辨識信心、人物公司歸屬及差異**；來源無法確證時顯示未知或推定，不可編造原生 Illustrator 物件身分與精確字寬。
  4. 測試在高倍率下**拖動標記候選框**、拖動畫布視角、以及移動真正模板物件三種手勢／模式；操作標記框不可實際更動原 .ai、已發布模板、字級、Logo 真實幾何或卡片物理尺寸。取消／撤銷更正須復原標記中介資料，不得將原始內容覆寫。
  5. 使用同類低風險且可驗證的標記與含姓名／公司歸屬混淆、跨作品混入、Logo 框切掉圖文、來源證據不足的高風險樣本，確定僅**明確勾選的低風險集合**可在使用者確認後批次核准，高風險須逐筆詳審，不可把 AI 候選自動列為正式已確認訓練真值。
  6. 更正流程應明確顯示 AI 待審／人工修正待確認／已確認／拒絕／隔離等狀態，具備改前改後對照、Undo／Redo、來源版本記錄與明確人工確認；單件作品更正只促成**受影響作品及依賴結果增量重分析**，不自動修改其他作品、發布模板或生成永久全域規則。
  7. 人工確認後對框位超出作品邊界、欄位重疊、必要欄位缺漏、文字／Logo 歸屬不正確、UI-013 固定字級及適用印前品質 Gate 重新檢查。未修正的歧義、來源不明、對應衝突須留在例外中心，不能假稱驗證 PASS。
  8. 本段全部為**待執行的驗收規劃**；目前沒有實際可操作智慧框、標記快捷工具、批次審核功能或已完成的 AI 訓練測試。

- **UI-040 智慧標記完整性與跨文件可重用雜訊排除驗收（尚未執行）**：
  1. 用合法或匿名 .ai 樣本設計**漏標、重複框、不同作品錯配、人物／公司歸屬衝突、完整 Logo 被切掉圖文**及合法重疊／含有多物件的複合 Logo 框等正反例，驗證問題總覽按可信證據分級、可定位來源、可提出有前後比較的建議，不得因框相交或同字串就直接判錯／刪除。
  2. 在來源作品外部、校稿流程註記、工單標籤等明確非設計場景放置**「問題單」「已校稿」**的文字，人工首度勾選**「剔除並記住，後續相同情境自動排除」**，檢查 GUI 展示完整字串、來源／位置條件、例外及影響範圍；依 UI-007／UI-008 一次取得正式人為核准後，生成有來源／版本／規則狀態的持久規則。
  3. 匯入**多份後續新 .ai 文件／多個作品**，於相同已核准的實際情境重現完全相同雜訊字串，驗證系統**直接自動排除名片欄位標記及模板學習候選、不重複彈出逐檔確認問題**，並清楚紀錄命中規則、來源及排除原因；若來源條件不符或規則尚待審，不能自動剔除。
  4. 設計負例：公司名稱或真實文案**包含**「已校稿」字樣、正式 Logo 內有相似文字、OCR 錯字、僅子字串匹配、標點／空白／全半形差異、來源非同類、同名而實際不同人物與公司。未核准模糊擴充或不滿足規則條件者不得自動排除；有風險的應保留資料並送人工例外中心，不可丟失名片真正的內容。
  5. 驗證「**只排除此作品**」不生成跨文件正式規則；「**剔除並記住**」仍須通過 UI-008 的一次最終人工核准，而不是單例校正後偷自動提升全域規則。已核准規則遇到一致、無衝突新檔自動執行，無須再次詢問；遇到新歧義或與既有人工確認的真實欄位衝突才提出獨立審核。
  6. 原始 Illustrator 來源物件及像素、已發布模板與真正正式列印成品不可因學習雜訊排除而被刪除／塗白／覆寫；需辨識「從訓練資料排除」與「要實際從模板草稿印刷版面刪除元素」是不同且需另外授權的動作。
  7. 每個自動排除結果可查詢規則名稱／確切命中條件、版本、來源作品及理由；模擬**使用者回報誤判、停用／回滾規則與恢復個別標記**，測試只重分析真正受影響的作品及依賴項、不覆蓋原先人工核准欄位事實，版本追溯仍完整。
  8. AI 完整性檢查、規則執行及正式輸出 Gate 皆須保留證據：若誤排除真實欄位、Logo 內文或重要歸屬未決，不能因已啟用雜訊規則而宣稱訓練成功或印刷品質 PASS。規則追溯不能意外蒐集或保存超出 UI-042 已正式核准的客戶主檔、購買／尺寸／版型及訓練斷點範圍之工作或訂單資料（舊版不保存客戶歷史的限制已由 UI-042 部分更新）。
  9. 這些均為**尚未執行的驗收規劃**，目前沒有進行實際雜訊學習、跨文件自動剔除、規則核准／回滾操作、AI 訓練或任何程式開發。

- **UI-041 雜訊規則庫追溯、誤判恢復、例外及安全回滾驗收（尚未執行）**：
  1. 以已核准「問題單」「已校稿」等**具體來源／區域條件**的版本化雜訊規則，驗證管理中心能列出規則全文、核准／啟用／停用／候選狀態、來源與版本，依字串／適用情境／狀態搜尋；沒有實測的命中統計不得假造。
  2. 在多份獲授權或匿名化的不同 .ai 新檔及單檔多作品案例中，讓既有已核准規則自動命中**合法同情境的完整字串**；確認無逐檔重複詢問，命中可查到具體檔案／畫板／作品／標記框、規則版本、比對依據、真正排除／保留／衝突狀態並可跳到原稿。
  3. 建立正反例：真實公司名稱包含「已校稿」、複合 Logo 內文字、姓名正式欄位、校稿標籤及 OCR 模糊字串，驗證精確已核准白名單或人工已核准欄位不會被普通雜訊規則悄悄排除；白名單／雜訊規則衝突、來源不明須維持原資料並進例外中心，不放大規則到未核准子字串／同義詞情境。
  4. 在已自動排除清單選取單一誤判項目，測試「**只恢復此項**」不影響其他新檔合法命中，原本人工已確認之來源／語意不被抹除；從畫布標記回報不是雜訊亦可反向定位規則與命中紀錄。
  5. 對「新增可重用例外／白名單」進行條件、來源證據、影響清單與反例檢查；需 UI-008 正式人工核准及版本記錄方能跨作品使用。未核准白名單不得默默放行，已確認真實欄位的保護不因啟用雜訊規則而失效。
  6. 對規則停用、修改、撤銷或回滾，先顯示**預期恢復／再排除項目及已確認人工標記／下游候選**，後執行有確認、有版本、有失敗狀態的操作；只重分析受影響作品及依賴，不修改其他已確認模板及已輸出的正式成品，不在原始 Illustrator 物件上刪字或塗白。
  7. 注入規則更新中斷、命中索引不一致或源資料不可得等故障，GUI 不能假稱所有項目已回滾；需明確保留待核實或安全阻擋狀態，未能驗證的品質 Gate 不得轉 PASS。實際安全持久化、復原與故障注入仍待未來工程實作驗證。
  8. 規則及必要來源／核准版本資訊可持久管理，測試不得僅因雜訊命中追溯而增建未授權的客戶工作／訂單資料；UI-042 已另明確核准的持久客戶主檔及已核實購買／尺寸／版型關聯不在此禁令內；個資與原稿不得自行送 GitHub 或外部系統。
  9. 此段為**尚未執行的驗收設計**；目前沒有真正啟動雜訊規則庫、回滾、白名單、AI 訓練或任何程式開發。

- **UI-042 訓練中斷恢復、異名同內容去重與持久客戶重訂資料庫驗收（尚未執行）**：
  1. 建立多來源 .ai 訓練集（單檔多作品、多畫板、不同尺寸），核對訓練儀表板可追溯**檔案→實際作品→解析／標記／雜訊規則／訓練／人工審核／驗證**的真實狀態、完成數與阻擋原因；進度和完成率必須依實際資料計算，不得編造或把「已解析」當成「已通過審核」。
  2. **關閉 Windows 程式後再開啟**，核實持久來源索引、每檔及作品完成／待審／中斷／失敗狀態、規則和解析版本、足夠的檢查點與已驗證成果依舊存在；斷電／寫入中斷／更新版本後，須檢查快取有效性，能接續只需處理的項目，且不誤宣告已完成、不重複寫入或跳過人工批准。
  3. 提供**內容位元完全相同但檔名不同**的 A001.ai 與 B002.ai，且來源各自使用不同客戶編號：檢查安全雜湊如 SHA-256 與可選實體比對後**只分析內容一次**，卻完整保留 A001/B002 不同原名、來源路徑與可能的兩個客戶關聯，**不刪原始檔、不消除第二個編號、不自動合併兩位客戶**；也驗證同名不同位元、外觀近似但位元不同、作品部分重複、不同模型版本需重分析的分層負例。
  4. 來源檔名是客戶編號的情境，測試擷取原檔名／檔名主體、附加版本尾碼、Windows 路徑／大小寫、重名衝突與可核對規則；**候選編號不等於已確認身分**，遇同雜湊跨客戶、同編號不同資訊、多份同名檔需人工審核，不得將其他人的電話、手機、LINE、IG 或版型錯接。
  5. 使用授權／匿名化的客戶資料正反例，驗證正式客戶編號能與**姓名、私人電話、行動電話、LINE、IG、人物／公司、門禁卡多種實體尺寸，以及每尺寸相應已核准版型／版本**關聯；一個客戶可以有多個聯絡人及多尺寸多款式，資料由可靠來源及必要人工核實，不能把同名、共用電話或 Logo 相似自動判成同一客戶。
  6. 對「**來源稿有某尺寸／樣式，但並無實際購買證據**」的樣本核對資料庫須標示為「曾設計／待確認」而非「已購買」。只有使用者確認或具體可驗證交易依據才能將特定尺寸、版型寫入已購買關聯；修改或撤銷確認要留有可回復記錄並更新受影響查詢候選。
  7. 從新作業的舊客戶查找入口，分別輸入**客戶編號、姓名、手機、私人電話、LINE、IG**，測試相同資訊、多結果、資料修改及來源不足的歧義提示；使用者明確選定客戶及「沿用舊版型」後，需核對真實樣式來源與尺寸、Logo 同尺寸庫、原始／已發布版本、當次文字與字型可用性、UI-013 固定字級、安全區及印前 Gate，不能把歷史成品直接當新訂已驗證可印。
  8. 模擬 UI-039 標記更正及 UI-040／UI-041 雜訊規則新命中或回滾，驗證只對已失效／受影響作品及其依賴重新分析；完整性檢查、失敗重試和批次部分成功不可將未核准學習結果、待審客戶資料或未經驗證的購買紀錄宣稱 PASS。
  9. 審查**訓練索引、客戶資料庫、版型／Logo 庫、暫時製作草稿的儲存界限**，在本機正確保護個人電話、手機、LINE、IG 等個資，測試存取權、必要用途與告知、最小化、加密、備份／復原、更正、刪除、匯出及權限錯誤處理；未獲授權不能把真實客戶個資或原始 AI 檔上傳 GitHub／外部伺服器。資料庫持久化不等於無限保留所有未完成作業。
  10. 以上為**待執行的驗收設計**，尚未分析真實檔案內容、計算雜湊、建立客戶資料庫、恢復真實訓練或執行任何開發及驗證。

## Gate 2：去重與增量
- 位元重複、內容近似、作品重複、模板等效分層測試；來源保留；更動/未更動檔案增量分析有可驗證紀錄。

- **UI-020 複合公司 Logo 區域及占位語意驗證（2026-10-12 新增，尚未執行）**：
  1. 準備獲授權的真實或去識別測試 .ai 案例：公司名稱文字與符號同屬完整 Logo、Logo 外另有獨立公司名稱文字、多人共用公司、OCR 辨識錯誤、Logo/公司名稱部分遮蔽及混合向量/點陣素材。
  2. 檢驗模型是否以**覆蓋全部圖文的單一邏輯矩形框位**識別完整複合 Logo，並將其與公司實體關聯；保留輪廓／顏色／字形／布局比例／原始來源。不得把 OCR 文字單獨輸出為可替代 Logo 的一般欄位，也不得把 Logo 內字與 Logo 外獨立公司名稱混淆。
  3. 複合 Logo 的 OCR 結果僅能作**候選公司身分／邊界線索**；結果需結合 Illustrator 物件群組及視覺位置證據，可被使用者校正。低信心或跨越多元素的邊界不確定應進入例外審核；人工修正後能可追溯地重新分析受影響範圍。
  4. 驗證目前**公司名稱輸入為 Logo 放置框位語意占位**的路徑，不可將名稱文字轉成憑空生成的商標，且未具正確實際 Logo 時不可把占位預覽當成完成的真實品牌輸出。
  5. 將**未來實際 Logo 圖檔輸入口**列為未完成需求；建置後需用真實向量／點陣資產測試與公司連結、保留整體長寬比、框位對應、印前尺寸／品質驗證，失敗必須阻擋正式輸出。此處不主張該功能已建置。
  6. 複合 Logo 圖文需維持整體視覺內容，不適用 UI-013 可變文字欄位的自動字級／字寬重排；獨立公司名稱文字框則照常適用文字規則。

- **UI-021 公司 Logo 資料庫／占位預覽驗證（尚未執行）**：
  1. 驗證 AI 以圖像、Illustrator 物件關係及 OCR 等**線索**推定完整複合 Logo 矩形框位；畫布疊圖、來源物件清單、圖文包含性、修改邊界與合併／拆分、公司歸屬修改，以及不確定案例進例外中心後局部重分析，需有實際案例及可重現證據。
  2. 驗證**使用者手動匯入 Logo**與**AI 辨識 Logo 並提出待審核候選**兩種來源流程，正式庫只接受經**使用者明確核准**的資料；檢查拒絕、暫緩、重複／近似名稱、錯誤公司關聯、不完整圖文、來源不明與品質不足時皆不能暗中入庫。
  3. Logo 資料庫須能持久保存已核准資產、可追溯原始來源、公司關聯、審核與版本資訊；與客戶當次工作歷史分離；測試禁止未授權的原始客戶圖檔外傳或上傳程式碼庫。
  4. 輸入公司名但找不到**已核准且符合該公司身分的真實 Logo**時，預覽須按訓練取得的 Logo **完整矩形框位**繪製同尺寸**黑底矩形＋白色公司名稱文字**，標記**占位預覽、非真實商標**；不能借用其他公司的 Logo、臆造圖案或把暫時白字當成訓練資產。
  5. 黑底白字 fallback 不得因過長公司名改變正式 Logo 框位或突破安全區，也不得在 Logo 為必要內容時冒充品質驗證已通過，**正式輸出應受阻擋**；替換為來源合格的真實複合 Logo 後，重新檢驗長寬比例、印刷清晰度、公司歸屬及格式。
  6. **本段全屬待測項目**，不可把列入驗證計畫當成 GUI、資料庫或自動辨識已完成。

- **UI-022 共用 Logo 資產庫管理 GUI 專項驗收（尚未執行）**：
  1. 檢查「已核准 Logo」「AI 待審核候選」「人工匯入」三種檢視，搜尋、來源／狀態篩選、原圖放大、向量／點陣來源、公司身分、圖文完整性與品質資訊均可正確對照。
  2. 以 OCR 同字串但不同公司、不同 Logo、近似圖形、重複匯入及來源不明樣本驗證：系統只能提出候選，不能以相似度自動核准、合併、覆寫已核准 Logo；AI 候選未經人工核准不得進正式庫。
  3. 驗證人工匯入、AI 候選核准／拒絕、版本更新與撤銷有明確動作及可追溯記錄；公司共有 Logo 被修改時，能顯示受影響引用關係，不能隱藏變更。
  4. **依 UI-023 後續優先決策**，訓練區與當次輸入區只共用**相同卡片實體尺寸**之已核准 Logo 庫；不同尺寸須分庫、分層訓練與獨立核准，不能讓管理畫面共用導致跨尺寸一般調用。當前尺寸沒有合格 Logo 時維持 UI-021 黑底白字占位預覽，不能拿其他尺寸 Logo 或未審核候選替代正式輸出資產。
  5. 驗收使用匿名化或有明確授權素材；Logo 原始資產不可未經授權上傳 GitHub。本段是待開發後的驗證計畫，**未完成實作／測試**。

- **UI-023 尺寸獨立 Logo 庫與跨尺寸預測例外驗證（尚未執行）**：
  1. 對至少兩個不同卡片實體尺寸建立匿名化／獲授權 Logo 測試素材；確認 AI 能依來源尺寸分層識別、建立獨立候選、人工核准狀態與版本，且不同尺寸不可因公司名或圖形一致就自動共享核准。
  2. 對已知尺寸的正常模板匹配、資料輸入、預覽及 PDF／PNG／JPG 正式輸出建立隔離測試：只允許選用**該尺寸庫已核准、未停用且品質合格**的 Logo；跨尺寸可見於管理不等於可直接調用。
  3. 本尺寸缺 Logo、其他尺寸有同公司 Logo 時，仍只顯示與本尺寸完整框位同尺寸的**黑底白字占位**，並保持原必要 Logo 輸出阻擋；不能暗中回退到其他尺寸。
  4. 只有切入**新尺寸模板預測**工作流程，才允許讀取全部尺寸 Logo 庫作**候選參考**；每個候選清楚記錄來源尺寸、新目標尺寸及品質／比例風險，須經新尺寸的幾何、印刷、公司身分與人工審核後才能入該尺寸正式庫。返回已知尺寸預覽時必須恢復嚴格尺寸隔離。
  5. 同公司多個已核准版本或橫直變體時，驗證系統在同尺寸範圍內比較與推薦；單一明確合格者才可自動預覽，歧義需要人工確認，當次選定版本及尺寸不可靜默替換。
  6. 所有測試均屬待執行驗收計畫，不代表已開始訓練、建立 Logo 庫或輸出程式。

- **UI-024 各尺寸 Logo 庫導覽與新尺寸預測專區驗證（尚未執行）**：
  1. 用至少兩種卡片實體尺寸的匿名化或經授權案例，驗證尺寸樹狀導覽切換時只顯示當前尺寸的公司、Logo 版本、AI 候選與人工匯入項目，並明顯顯示所屬尺寸／審核狀態。
  2. 確認一般 Logo 審核、查找、版本比較、輸入預覽與正式輸出不能因操作其他尺寸、跨庫同名公司、同圖案版本或瀏覽器/介面狀態殘留而混用不同尺寸資料。
  3. 驗證進入獨立新尺寸模板預測專區後，才可參考所有已授權尺寸 Logo 庫；跨尺寸候選須顯示來源尺寸、目標尺寸、來源公司、Logo 版本、完整圖文與品質／比例風險。這些候選一律不是新尺寸已核准正式資產。
  4. 驗證使用者拒絕、待修正、缺乏驗證或未核准的新尺寸候選無法入正式庫；通過新尺寸幾何／印刷品質驗證且明確人工核准後才加入其尺寸獨立庫。
  5. 退出新尺寸預測或切換回已知尺寸時須恢復嚴格庫隔離；本尺寸無已核准合格 Logo，保留 UI-021 同框位黑色矩形及白色公司名稱占位預覽，禁止將占位或跨尺寸候選冒充真實 Logo 進正式輸出。
  6. 本段只是未來驗收條件；目前未實作 UI、資料庫或任何跨尺寸預測／訓練。

- **UI-032 字型管理中心、智慧匹配及安裝授權驗收（尚未執行）**：
  1. 使用經授權的 Windows 既有字型、本機匯入字型、原稿缺失／未知字型、不同家族但相似字型及名稱別名案例，核對 GUI 的三種來源／狀態、字型身分與對照；「僅外觀近似」不能顯示為「已找回來源原字型」。
  2. 測試合法字型檔人工選取、來源及授權查核、有效與損壞／不支援格式、字型款式及中文／英數／符號字形涵蓋。可供程式內使用的字型須與 Windows 已安裝狀態明確區分；不能因匯入就偷偷安裝系統或把字型檔上傳 GitHub。
  3. 單獨測試 Windows 字型安裝須先向使用者列出來源、授權、目前使用者或全系統影響、可能管理員權限、確認／取消及失敗復原說明。取消或未取得明確授權時 Windows 字型狀態不得變動；不得在 AI 匹配時自行下載不明授權字型。
  4. 使用字型候選比對原稿視覺、實際字寬、必要中文字／符號缺字、字形差異及授權，確認候選僅為建議；更換字型需能追蹤受影響欄位、模板與版本差異，高風險案件需依既有例外中心及 UI-008 規則人工審核，不能把單次選擇無聲套成全域永久替代。
  5. 對字型替換、安裝後字型變動及字型停用，重做 UI-013 固定字級、文字寬度／合法水平縮放、可讀性、無重疊、安全區、完整性與輸出檢查；不可擅自因字數或換字型改字級，也不能把複合 Logo 內字當作一般文字替換。
  6. 核實程式內可預覽與正式 PDF 字型嵌入／PNG／JPG 正確轉出、印刷品質及使用授權是不同檢查；來源不足、禁止嵌入或品質不合格，正式輸出不得宣告通過，僅允許清楚標示問題的診斷預覽。
  7. 程式內字型載入、可用副檔名、Windows 安裝權限及回復能力均須在後續原型與真實測試後確認；**本段只是尚未執行的驗證計畫，沒有開始開發、掃描或安裝字型**。

- **UI-033 字型替代影響範圍與風險分級批次審核驗收（尚未執行）**：
  1. 以多卡片尺寸、跨模板、同一缺失字型影響姓名、公司外部獨立文字、職稱、電話等不同欄位的匿名化／獲授權資料，驗證替代前列出**全部實際受影響模板、版本、尺寸、人物／公司及文字框**，不存在漏列／跨模板誤套用，並可定位原稿。
  2. 對每欄比對候選替代字型前後的來源證據、中文字及英數符號覆蓋、字形、真實字寬、水平縮放需求、溢出、重疊、安全區與實體印刷品質；若原始字型資料缺失而無法量測，須清楚標示**未知或估算**，不得編造原稿字寬或宣稱完全一致。
  3. 建立已核准低風險、高風險來源或語意不確定、實際溢出／缺字硬性失敗三組案例，確認風險分組有可核實依據；低風險僅在使用者勾選具體項目並確認影響範圍後才可批次使用，高風險必須逐筆審核，硬性失敗或缺乏充分證據不可直接通過。
  4. 測試只選 3 個文字框、其餘相同來源字型文字框不選時，**未選取項目不改動**；再次測試替代版本與模板草稿差異、Undo／Redo／回復及已發布模板 UI-010 保護；**不會把當次替代自動建立成 UI-008 永久全域規則**。
  5. 替代確認後以同尺寸已決定的欄位字級重測 UI-013：不因文字長度／候選字型差異自動改字級，僅在核准允許的水平字寬、字距與對齊界限內試排；字形缺失、文字溢出、重疊、語意歸屬或安全區有硬性問題時須顯示無解／待修正，禁止正式印刷成品通過 Gate。
  6. UI-020 複合 Logo 內部文字不可進一般欄位字型替代清單；UI-032 Windows 系統字型安裝必須是另行取得明確授權的不同操作。對同一組部分成功／部分失敗的批次，GUI 應逐筆顯示結果而非宣告全組合格。
  7. 所有項目皆為**待執行的驗收設計**；尚未開發字型替代、批次審核與回復機制，亦沒有執行真實字型或輸出品質測試。

- **UI-034 畫布／物件樹／屬性面板同步與安全多選驗收（尚未執行）**：
